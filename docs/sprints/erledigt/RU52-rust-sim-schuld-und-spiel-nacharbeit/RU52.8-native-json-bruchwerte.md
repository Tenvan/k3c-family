## Ziel

Rust liest `data/native.json` wie Go: Zahlenfelder als `f64`, ein ausdrückliches `0` ist von „fehlt“ unterscheidbar (B-1110).

## Kontext

`k3c_data::native::Native` hat `i64`-Felder, Go liest `float64`. Ein Bruchwert (4.5) gilt in Rust als unlesbar (Standardwerte); `slowLogEverySeconds: 0` ist von „fehlt“ nicht zu unterscheiden (Rust 5 s, Go 0). Die Datei enthält heute nur ganze Zahlen, die Werte bleiben unverändert. Gefunden in RU29.2.

## Erlaubte Dateien

- `rust/crates/k3c-data/src/native.rs`
- `rust/crates/k3c-data/tests/**`

## Nicht-Ziele

Werte in `data/native.json` ändern, Aufrufer außerhalb `k3c-data` (Befund ins Ergebnis, wenn der Typ der Felder deren Anpassung braucht, dann `as`-Umrechnung im Getter statt Feldtyp ändern), Go-Code.

## Schritte

1. Go-Leser (`native.json`, Standardwerte) und `native.rs` lesen.

5. Ergebnis in Session und B-1110, Status `fertig`, ein Commit.

## Ergebnis

AC-08 geprüft: `Native.step_budget_ms` und `slow_log_every_seconds` sind `Option<f64>` (fehlt = `None`, ausdrückliche 0 = `Some(0.0)`), `voyage.seconds`/`arcPx`/`wavePx` sind `f64`. Neuer Test `native::tests::bruch_null_und_fehlend` (4.5, 0, fehlend); `cargo test -p k3c-data` (26, inkl. Go-Golden-Vergleich), `cargo build --workspace`, Clippy und fmt grün. Werte in `data/native.json` unverändert.

Abweichung: `devtools/chronicle.rs` (Aufrufer, außerhalb der erlaubten Dateien) musste an den Feldtyp angepasst werden: `unwrap_or(Standard)` statt `as`-Umrechnung; dabei entfällt dort die Rust-eigene Korrektur `slowLogEverySeconds <= 0 → 5`, damit `0` wie in Go `0` bleibt (Go korrigiert nur `stepBudgetMs`). `task check:diff` lokal rot nur durch bekannte fremde Fehler.
