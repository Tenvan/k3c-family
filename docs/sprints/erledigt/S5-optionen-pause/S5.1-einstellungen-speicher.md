## Ziel

Die Optionen (Lautstärke Musik und SFX, Screenshake aus, Flash aus, Farbschwäche-Symbole, Sprache) liegen als reine, getestete Funktionen mit Speicher je Gerät in `src/core/settings.ts` vor; Audio (B-011) und Juice (B-164) können sie später nur lesen.

## Kontext

- Es gibt noch keine Einstellungen. `src/core/saveStore.ts` speichert nur Spielstände (Muster dort: `localStorage` immer in `try/catch`, Schlüssel `k3c-save-<slot>`), `src/core/clientLog.ts` ist ein weiteres Beispiel für eine kleine Datei in `src/core/` mit Test daneben (`clientLog.test.ts`, Vitest).
- Beschlossen (B-146 › Anforderungen): Standard ist alles an, Lautstärke 100 %; Werte außerhalb 0–100 % werden begrenzt; `localStorage` gesperrt, gelöscht oder kaputt (kein gültiges JSON, falsche Typen) → Standardwerte, kein Absturz. Zusätzlich beschlossen (B-172, Q05): Feld `language` mit `de` (Standard) oder `en`; unbekannter gespeicherter Wert → `de`.
- Vorschlag zur Form (nicht beschlossen, nur Ausgangspunkt): `interface Settings { musicVolume: number; sfxVolume: number; screenshake: boolean; flash: boolean; colorblindSymbols: boolean; language: 'de' | 'en' }` mit Lautstärken als ganze Prozent 0–100. Flags positiv benannt (`screenshake: true` = Schüttelei an), damit „aus“ in der Szene ein Schalter auf `false` ist.
- Testbarkeit: Speicher als Parameter (`Storage`-ähnliches Objekt mit `getItem`/`setItem`), Standard `globalThis.localStorage` nur beim Aufruf auslesen, weil der Zugriff selbst werfen kann. Vitest läuft ohne DOM, der Test übergibt ein Fake-Objekt.
- Schichtgrenze: `src/core` importiert nichts aus `src/scenes`; keine Logik in `src/model`. Kein `Math.random()`. Keine neue Abhängigkeit.
- Ob ein Wert „je Gerät“ gilt, ergibt sich aus dem Speicherort: der `localStorage` des Browsers (auf dem Server wird nichts gespeichert, siehe B-146).
