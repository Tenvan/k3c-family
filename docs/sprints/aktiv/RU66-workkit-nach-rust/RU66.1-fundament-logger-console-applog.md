### Warum diese Reihenfolge

`mcpkit` importiert `applog`, `usage` und `proc`; `applog` importiert `conlog` und `console`. Der Port läuft deshalb von unten nach oben: zuerst Logging und Konsolenpuffer, `mcp` folgt in RU66.3/RU66.4.

Nie `std::env::temp_dir()`.
6. **Modul `logger`** (Gegenstück zu Go `log/slog`, Vertrag für alle späteren Sessions):
   - `pub enum Level { Debug, Info, Warn, Error }` (slog-Werte −4, 0, 4, 8; Namen `DEBUG`, `INFO`, `WARN`, `ERROR`; `PartialOrd`).
   - `pub type Attrs = Vec<(String, serde_json::Value)>;` und `pub struct Record { pub time: chrono::DateTime<chrono::Local>, pub level: Level, pub msg: String, pub attrs: Attrs }`.
   - `pub trait Sink: Send + Sync { fn enabled(&self, level: Level) -> bool; fn handle(&self, r: &Record) -> std::io::Result<()>; }`.
   - `#[derive(Clone)] pub struct Logger` (intern `Arc<Vec<Box<dyn Sink>>>` und `Arc<Attrs>`): `new(sinks)`, `discard()`, `with(&self, attrs: &[(&str, Value)]) -> Logger` (wie slog `Logger.With`: Attribute vor denen des Aufrufs), `log(level, msg, attrs)`, `debug`, `info`, `warn`, `error` (je `&self, msg: &str, attrs: &[(&str, serde_json::Value)]`). Fehler einer Senke werden verworfen (wie slog). Aufruf: `log.info("🔁 server neu gestartet", &[("ns", json!("mcp")), ("url", json!(url))])`.
   - `pub fn time_millis(t: &DateTime<Local>) -> String` (RFC 3339 mit Millisekunden und Offset, bei Offset 0 `Z`; Go `2006-01-02T15:04:05.000Z07:00`); `applog` und später `mcp::stats` nutzen sie.
   - `WithGroup` wird nicht portiert (kein Aufrufer in Workbench, Studio, workkit); im Ergebnis nennen.
7. **`conlog`:** `ConsoleSink::new(w: Box<dyn std::io::Write + Send>, level: Level, color: bool)` implementiert `Sink` und schreibt die Zeile exakt wie `conlog.Handler.Handle` (Zeit `%H:%M:%S%.3f` lokal grau, Level-Wort farbig, Emoji aus `TOPICS` vor `[ns]` cyan, Meldung fett bzw. fett-rot ab ERROR, dann ` key=value` mit `quote`-Regel aus Go). `ns` kommt aus Logger- oder Aufruf-Attributen und erscheint nie als `ns=`. `pub const TOPICS: &[(&str, &str)]` wortgleich aus `engine/conlog/conlog.go`, `pub fn color() -> bool` (aus bei gesetztem `NO_COLOR`).
8. **`console`:** `Line` mit serde-Namen `source`, `stream`, `text`, `seq`; `Store::new(capacity, on_line: Option<Box<dyn Fn(Line) + Send>>)` mit `DEFAULT_CAPACITY = 2000`, Benachrichtigung über `std::sync::mpsc::sync_channel(256)` und `try_send` in einem eigenen Thread (blockiert nie, volle Queue verliert Benachrichtigungen, nie Zeilen); `add`, `reset`, `tail`, `sources`, `stats`, `close`. `LineWriter` (writer.go) implementiert `std::io::Write` plus `flush_line()`; `clean` wie Go. Nur `std`, kein tokio.
9. **`applog`:** Konstanten `SOURCE = "k3c-workbench"`, `LEVEL_ENV = "K3C_DEV_LOG_LEVEL"`, `MAX_FILE_SIZE = 10 << 20`; `parse_level`, `levels`, `rotate`; `open(logs_dir, store: Arc<console::Store>)` und `open_named(logs_dir, source, store) -> (Log, Option<std::io::Error>)` (Logger auch bei Dateifehler nutzbar, wie Go); `Log::logger()`, `Log::close()`. JSON-Senke schreibt **von Hand in fester Reihenfolge** `{"time":…,"level":…,"msg":…,<attrs…>}` (kein `preserve_order`-Feature), Zeit mit `logger::time_millis` wie slog JSONHandler. Spiegel in den Konsolenpuffer über `ConsoleSink` mit Farbe immer an (wie Go).
