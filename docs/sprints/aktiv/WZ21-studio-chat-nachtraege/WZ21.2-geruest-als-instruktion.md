## Ziel

Auf `develop` schickt der Studio-Chat bei Welt-Aufträgen das Grundgerüst selbst als System-Instruktion mit; 🧑 schreibt nur den Wunsch, der Knopf „Prompt-Grundgerüst“ ist weg (B-516).

## Kontext

- Gerüst: `tools/k3c-studio/backend/app_world_prompt.go` › `PlanWorldPrompt` baut den Text aus den Daten und hängt am Ende `promptWishes` („MEINE WÜNSCHE:“) an. Die Antwort prüft `PlanWorldAnswer`.
- CLI-Aufruf: `backend/chat_cli.go` › `chatArgs(o chatOptions)` (Sicherheits-Argumente fest, Modell/Denkstufe aus `chat_options.go`), `chatCLI.run(ctx, prompt, opts, emit)` schreibt den Prompt auf stdin, Arbeitsordner `chatCLI.workDir` (`%TEMP%/k3c-studio-chat`).
- HTTP: `backend/chat_http.go` › `chatRequest {Chat, Text, Provider, Model, Effort}`, `readChatRequest` prüft; der Verlauf (höchstens `chatHistoryMax`) geht mit in den Prompt.
- Test-Ersatz: `backend/chat_fake_test.go` (`TestMain`, Modi `echo`, `hang`, `login`; `K3C_CHAT_FAKE_ARGS` schreibt Argumente und Arbeitsordner in eine Datei). Tests: `chat_cli_test.go`, `chat_http_test.go`.
- Frontend: `frontend/src/chat/chatBridge.ts` (`registerDraftLoader`/`useCanLoadDraft` = Welten Editor offen; `fillChat`/`registerChatFill` füllen das Eingabefeld), Anfrage in `chatAdapter.ts`/`useChatSession.ts`, Knopf in `frontend/src/world/WorldDraftEditor.tsx` (`fillPrompt`), Binding `planWorldPrompt` in `api/http.ts`, `api/worldTypes.ts`, `api/mockWorldDraft.ts`, `api/mockPlan.ts`. Tests: `world/ChatDraft.test.tsx`, `chat/ChatPanel.test.tsx`.
- CLI 2.1.304 kennt `--append-system-prompt-file <datei>`; Datei statt Argument, weil Windows die Kommandozeile auf 32 KiB begrenzt.
- Fallstrick: Mehrere Chats können gleichzeitig antworten (je Chat eine), die Gerüst-Datei braucht daher einen eindeutigen Namen je Lauf und wird danach gelöscht.
