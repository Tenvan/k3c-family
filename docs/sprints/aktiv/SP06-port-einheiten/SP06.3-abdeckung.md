# SP06.3 · Golden-Abdeckung der Simulation auf mindestens 90 %

- **Status:** offen
- **Typ:** Umsetzung

- **Abhängig von:** SP06.2

## Ziel

Die Tests in `engine/sim` führen mindestens 90 % der Anweisungen aus. Was dabei auf TS-Abweichungen stößt, ist in Go
behoben.

## Kontext

- Messen: `go test -coverprofile="$TEMP/sim.cover" ./engine/sim/` und danach `go tool cover -func="$TEMP/sim.cover"`.
  Die Abdeckung zählt Anweisungen, die ein Test ausführt. Weil jeder Golden-Lauf jeden Snapshot vollständig vergleicht,
  fällt eine Abweichung in einem ausgeführten Pfad spätestens im nächsten Snapshot auf.
- Bekannte Lücken aus SP05.3 (B-074): `carry` und Vorrat, `stepSites` mit Materialabzug, Bauen, Bögen und
  `fetchBow`, Turm-Posten, Truhen, `refundPending`. Vermutet (ungeprüft), weil kein Lauf es erzwingt: Burg-Fall,
  `stealsGold`, Fernkämpfer gegen Türme, zerstörte Mauern, Tiefe 2 mit Welle (`math.Pow`), Treppen-Wechsel.
- Mittel, in dieser Reihenfolge:
  1. Neue `sim-*`-Läufe in `tests/golden.test.ts` (Ausnahme INF). Ein Lauf darf sein Eingabe-Skript aus dem Level
     ableiten, z. B. zu Bäumen laufen und dort bezahlen. Aufgezeichnet wird es wie bisher als Segmente. Ideen:
     `forest-aufbau` (Bäume markieren, Mauer und Werkstatt bezahlen, Bögen kaufen), `forest-belagerung` (hohe
     `cycleSpeed`, kaum Verteidigung → Burg fällt), `mine-welle` (Biom mine, hohe `cycleSpeed` → Welle in Tiefe 2).
     Für lange Läufe ist `snapshotEvery` 60 erlaubt (Feld je Lauf statt fester Konstante).
  2. Treppen und Rückweg: die Fälle aus `src/world/sim/campaign.test.ts` als Go-Tests mit denselben Erwartungen.
  3. Pfade, die kein Lauf erreichen kann, im Ergebnis begründen, nicht künstlich erzwingen.
- Weicht ein neuer Lauf in Go ab, wird Go korrigiert, nie TS oder die Golden-Daten. Bestehende Golden-Dateien ändern
  sich nicht.

## Erlaubte Dateien

- `engine/sim/`
- Ausnahme (INF): `tests/golden.test.ts` (neue Läufe, `snapshotEvery` je Lauf), `testdata/golden/` (nur neue Dateien)
- `docs/sprints/`, `docs/backlog/`

## Nicht-Ziele

Neue Mechaniken; Abdeckung außerhalb von `engine/sim`; Änderungen an `src/` oder an bestehenden Golden-Dateien.

## Schritte

1. Branch anlegen, `Status: in Arbeit`. Abdeckung messen, Ausgangswert im Ergebnis festhalten.
2. Läufe ergänzen, `task golden`, Go-Test grün machen (Go korrigieren). Wiederholen, bis die Abdeckung ≥ 90 % ist.
3. Treppen-Fälle aus `campaign.test.ts` als Go-Tests.
4. Größe der Golden-Daten prüfen (≤ 8 MB gesamt).
5. `task check`, `task check:go` → grün. B-074 auf `erledigt`. Ergebnis mit Abdeckung je Funktion unter 50 % und
   Begründung, lokal mergen.
