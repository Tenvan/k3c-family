- **Kopierwerkzeug:** `tools/sync/` (Paket `main` im Wurzel-Modul), beide Taskfiles rufen `go run ./tools/sync` aus der Wurzel; `ci.yml` und `release.yml` nehmen `go.mod`/`go.sum` der Wurzel statt `native/k3c-game`.
- **Messskript:** `tools/measure/measure.ps1` und `messen.cmd`; Pfade zur Wurzel über `$up` (im Repo zwei Ebenen, im Paket eine), Zweig `-Engine game` ohne EXE gibt die Referenz aus (geprüft, Exit 0); Taskfile und Doku zeigen auf den neuen Ort.
- **Workbench:** `studioview` startet `rust/target/release/k3c-game.exe` (Arbeitsordner Wurzel), dann `dist/k3c-game/k3c-game.exe`; Bau-Hinweis `task build`; Tests (`studioview`, `app_studio_test`, `GameOpen.test.tsx`) angepasst. Die Rust-EXE versteht `--saves`, `--load`, `--players` (Tests in `game/scene_tests.rs`), also kein Halt.

Geprüft: `go test ./tools/sync ./tools/rustpaket` grün, `go test ./internal/studioview` und `go test . -run Studio` (tools/k3c-workbench) grün, `cargo test -p k3c-game -p k3c-rig` grün (898 Lib-Tests), `cargo fmt` sauber, `task -n rust:game:build` zeigt `go run ./tools/sync` und `public/rig`. `task rust:game:build` (Paketbau) lief nicht lokal, das macht der CI-Job `rust`. `task check:diff` lokal: Stufe 1 meldet nur `go-lint` (golangci-lint fehlt auf diesem Rechner), alle übrigen Stufen grün.

**Abweichung:** `task gen:rig:check` ist nicht grün (250 Abweichungen, auch auf `main`, siehe unten); `public/rig` bleibt deshalb die exakte Kopie.
