## Ziel

k3c-dev zeigt per MCP den Zustand des laufenden Go-Servers: `server_status`, `rooms_list` und `room_snapshot` als verdichteter Text, bei fehlendem Server oder falschem Token mit verständlicher Meldung.

## Kontext

- Das Feld `Start-Commit` des Sprints setzt diese Session: `git rev-parse --short origin/main` vor dem Branch.
- Der Server (`engine/net/status.go`): `GET /api/status` mit `Authorization: Bearer <K3C_STATUS_TOKEN>`. Antwort `{version, startedAt, uptimeS, saves, reports, rooms: [room.Status], failures: [room.Failure]}`;
  `room.Status` (`engine/room/status.go`) = Info (Code, …) + `devices`, `monarchs` (taken/waiting/free je Index), `tick`, `tickMs {last, p99}`. `GET /api/status?room=CODE` liefert `room.Summary`
  (`code, depth, tick, phase, day, gold[], troops{}, enemies, castleHp, wave`), 404 „Raum nicht gefunden“. Ohne gesetztes Token antwortet der Server 404 (Diagnose aus), mit falschem Token 401.
- k3c-dev ist ein eigenes Go-Modul (`tools/k3c-dev`, Modul `k3c/tools/k3c-dev`): dieselbe JSON-Form lokal als kleine Structs lesen, **kein** Import aus `engine/` in dieser Session (das kommt in M6.2).
- Tool-Muster: `tools/k3c-dev/internal/mcpsrv/tools.go` (`add(s, &mcp.Tool{…}, handler)`, `readOnly()`), Beispiel `tools_gamedata.go`; Test-Server und Aufruf-Helfer in `roundtrip_test.go` (`connect`, `callText`). Jedes Tool braucht Beschreibung und Annotations (`TestAlleToolsMitBeschreibungUndAnnotations`), neue Tools gehören in `internal/mcpsrv/instructions.md`.
- Adresse und Token (Entscheidung 🧑 2026-10-01): Token aus `K3C_STATUS_TOKEN`; Adresse aus `K3C_SERVER_URL`, sonst `http://127.0.0.1:<K3C_HTTP_PORT oder 8080>`. Nur lesend (GET), Zeitlimit wenige Sekunden.
- Neue Datei(en) klein halten (≤ 400 Zeilen, Funktion ≤ 60): z. B. `tools_server.go` (Tools), `internal/serverapi/` (HTTP-Client und Verdichtung, testbar mit `httptest`).
