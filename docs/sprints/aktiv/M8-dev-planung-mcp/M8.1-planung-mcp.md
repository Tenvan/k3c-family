## Kontext

- Lesen gibt es schon: `tools/k3c-dev/internal/planning/planning.go` (`Load`, `ParseSprint`, `ParseTicket`, Regex `field`, `session`). Das Format bestimmen `docs/vorlagen/{ticket,sprint,session}.md`; geprüft wird es von `tests/planning.test.ts` (Felder, Überschriften, Status passend zum Ordner, Index `docs/backlog/README.md` mit Abschnitten „Offen“ und „Archiv“, Session-Tabelle ↔ Dateien, Fahrplan `docs/sprints/README.md` nennt jeden Ordner).
- Tools registrieren nur in `internal/mcpsrv/tools.go` › `register` (Helfer `add`, Annotations `readOnly()`; schreibende Tools mit `DestructiveHint` wie `check_run`). Handler-Muster: `tools_gamedata.go`; Roundtrip-Tests: `roundtrip_test.go`; Agenten-Text: `internal/mcpsrv/instructions.md` (neuer Abschnitt `## Planung`). `s.cfg.Root` ist die Repo-Wurzel.
- Der Wächter `planning.Watch` meldet geschriebene Dateien von selbst an die Oberfläche.
- Folgeänderungen (B-205 › Anforderungen): Ticket `erledigt`/`verworfen` → Datei nach `docs/backlog/archiv/`, Index-Zeile in „Archiv“ mit Pfad `archiv/…`; Session-Status → auch Zeile der Session-Tabelle; Sprint-`Status` → Ordner `geplant/`, `aktiv/`, `erledigt/` und Fahrplan-Zeile in die passende Tabelle (`## Aktiv`, `## Geplant …`/Einschiebbar, `## Erledigt`; Spalten je Tabelle siehe `docs/sprints/README.md`).
- Kein `git mv` nötig: `os.Rename` genügt, Git erkennt die Umbenennung beim Commit.
- Werte: Domäne `REG|SIM|SRV|CLI|PLAT|INF`, Ticket-Typ `Idee|Problem|Schuld|Frage`, Prio `hoch|mittel|niedrig|?`, Ticket-Status `offen|eingeplant|erledigt|verworfen`, Session-Status `offen|in Arbeit|fertig|blockiert`, Sprint-Status `geplant|aktiv|erledigt`, Spec `Entwurf|freigegeben|rückwirkend`.

1. Status setzen, committen, `git push -u origin sprint/m8` (Arbeitsweise › Autonomer Ablauf 2; Start-Commit steht schon in der README).
2. `internal/planning`: Auflösen einer ID zu Pfad (`B-NNN` in `backlog/` oder `backlog/archiv/`, Sprint-ID über Ordner-Präfix in `sprints/*/`, Session `ID.n` über die Datei-Spalte), Validierung der IDs und Kurznamen per Regex, Sperre (`sync.Mutex`) für alle Schreibwege.
3. Anlegen aus Vorlage: Kopfzeile und Felder ersetzen, übrige Abschnitte aus der Vorlage; Ticket-Nummer = höchste vorhandene (inkl. Archiv) + 1; Index-Zeile in „Offen“ anhängen; Sprint in `geplant/<ID>-<slug>/` mit Fahrplan-Zeile; Session-Datei plus Tabellenzeile in der Sprint-README.
4. Ändern: Feld ersetzen (nur Felder der Vorlage), Abschnitt `## <Name>` ersetzen; Folgeänderungen aus dem Kontext. `Spec: freigegeben` nur mit nicht leerem `Freigabe`.
5. Löschen: nur Sprint oder Session in `geplant/` mit `Spec: Entwurf` (Sprint) bzw. in einem solchen Sprint; samt Tabellen- und Fahrplanzeile.
6. Go-Tests im Temp-Repo (kleine Kopie von Vorlagen, Index und Fahrplan in `t.TempDir()`): alle Fälle aus B-205 › Beispiele und › Ausnahme- und Fehlerfälle; nach jedem Schreibfall mit `Load` zurücklesen.

8. `docs/arbeitsweise.md` (Abschnitt Ablage/Vorlagen und Autonomer Ablauf 5) und `CLAUDE.md` (Tickets/Sprints, „k3c-dev zuerst“): Planungsänderungen über die `plan_*`-Tools, Handarbeit nur, wenn k3c-dev nicht läuft.
