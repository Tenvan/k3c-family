## Ergebnis

AC-03 (B-1083/AC-01 bis AC-03) geprüft. Neue Datei `save_null_tests.rs` (5 Tests, Rohdaten aus `fixture(9)`; vor der Umsetzung 3 von 5 rot): `kopf_typ_nicht_ganzzahl_ist_fehler` (`version`/`island` als String, 1.5, Objekt → Fehler), `kopf_fehlend_ist_null` (`island` fehlend oder `null` → 0; `version` fehlend/`null` → `spielstand: Version 0, erwartet …`), `null_in_island_save_ist_standardwert` (`savedAt` String, `defeatedBosses`/`completed` Vec, `goldCollected` Zahl, `merchant` Option), `null_in_player_save_ist_standardwert` (`gold`, `skillBase`, `skills`, `slots`; zweiter Spieler unverändert), `pflichtfeld_null_ist_fehler` (`"seed": null` → `spielstand: Feld seed fehlt`). `cargo test --release -p k3c-sim island::` 105 grün (103 vorher ignorierte bleiben ignoriert), clippy und `cargo fmt --all --check` sauber, `save_tests.rs` und `save.rs` unverändert.

Umsetzung (`save_parse.rs`): `head_int` ersetzt `as_i64().unwrap_or(0)`: fehlend oder `null` = 0, jeder andere Nicht-Integer ein Fehler im Go-Text `spielstand: json: cannot unmarshal {string|number 1.5|object|bool|array} into Go struct field .version of type int` (bzw. `.island`; Go nennt beim anonymen Kopf-Struct `.version`). `1.0` und `1e2` sind in Go wie Rust Fehler. Für `null`: `strip_nulls` (rekursiv, 12 Zeilen) in `decode_island` vor `from_value`; `#[serde(default)]` füllt die Felder wieder; kürzer als `deserialize_with` an jedem Feld. Die Pflichtfeld-Prüfung läuft vorher, `null` zählt dort als fehlend. `null` als Array-Element bleibt (`"skills": [null]` bleibt ein Fehler).

Grenze: `strip_nulls` entfernt `null` auch in Maps innerhalb der gelesenen Werte (Go würde dort den Nullwert setzen). `save.rs` enthält keine Maps, das betrifft also nur freie `Value`-Teile; kein Test, nicht gesondert geprüft.
