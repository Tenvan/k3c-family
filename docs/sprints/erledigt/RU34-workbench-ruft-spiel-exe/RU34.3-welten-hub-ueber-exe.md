## Kontext

Schnittstelle `docs/standards/k3c-game-laeufe.md`, Starter `internal/gameexe`. Die Naht ist schon da: `tools/k3c-workbench/internal/world/level.go` (93: `Engine`, `Direct`) und `internal/hubplan/hubplan.go` (174: `Engine`, `Direct`) bekommen die Engine als Funktion `func(ctx, input []byte) (json.RawMessage, error)`. Gesetzt wird sie in `app_world.go` (`worldEngine = world.Direct`), `app_hub.go` (`hubEngine = hubplan.Direct`), `internal/mcpsrv/tools_world.go` (`worldEngine`) und `internal/mcpsrv/tools_hub.go` (`hubEngine`). Tests mit `simcli`: `internal/hubplan/editor_test.go`, `internal/world/world_test.go`, `app_world_test.go`.

**Vorentscheidungen:**
- `world.Direct` und `hubplan.Direct` werden ersetzt durch `world.Exe(root)` und `hubplan.Exe(root)`: `gameexe.Call(ctx, root, "world"|"hub", input, Opts{})`, Antwort ist `ev.Report`. Zeitlimit 30 s wie bisher. Die vier Zuweisungen zeigen auf `Exe`.
- Fehlt die EXE oder ist sie veraltet, zeigt der Editor die Meldung aus `gameexe` (Bau-Befehl) wie einen Engine-Fehler; kein Rückfall auf die Go-Engine.
- Tests: Die Editor-Tests nutzen eine Fake-Engine (Funktion mit fester Antwort aus `testdata/rust/runs/world-*.json` bzw. `hub-plan-hub7.json`, RU33.2), nicht die EXE; ein Test pro Paket mit echter EXE nur, wenn sie frisch ist, sonst `t.Skip`.
- Die Sim-Worktree-Regel B-925 (eigene Workbench je Sim-Worktree) hat nach dieser Session keinen Grund mehr für Level, Welten und Hub; Balancing folgt in RU40. Die Regel ändert 🧑: Die Session legt dazu ein Ticket an (Projekt RSU, Sprint RU40, Domäne DEV, Typ Schuld) und ändert `CLAUDE.md` nicht.
