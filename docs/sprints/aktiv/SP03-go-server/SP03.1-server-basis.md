## Ziel

`cmd/k3c-server` liefert `dist/` aus und beantwortet `/api/save`, `/api/report` und `/api/health` wie heute der
Node-Server; Go-Tests mit `httptest` ersetzen den Bash-Smoke-Test in `ci.yml`.

## Kontext

- Heute: `server/server.mjs` (Auslieferung `dist/`, MIME-Tabelle, `Cache-Control` HTML `no-cache`, sonst
  `public, max-age=31536000, immutable`; Pfad außerhalb `dist/` → 403; Verzeichnis → `index.html`; fehlt → 404
  `Nicht gefunden`; nur GET/HEAD, sonst 405; HTTP `K3C_HTTP_PORT` 8080, HTTPS `K3C_HTTPS_PORT` 8443 nur mit
  `certs/key.pem` + `certs/cert.pem`; ohne `dist/index.html` Abbruch mit Hinweis), `server/saves.mjs` (`GET/POST
  /api/save?slot=autosave`, Slot `^[a-z0-9-]{1,32}$`, höchstens 1 MB, JSON mit `campaignId` (Text) und `version` (Zahl),
  sonst 400; GET ohne Stand 404; anderes Spiel → alter Stand wird zu `<slot>-<savedAt>.json` umbenannt; Antwort
  `{"ok":true,"slot":…,"backup":…}`; `K3C_SAVES_DIR`), `server/reports.mjs` (`POST /api/report`, höchstens 256 KB,
  JSON mit `receivedAt` und `remoteAddress` ergänzt, Datei `reports/gamepad-<zeit>.json`, Antwort
  `{"ok":true,"file":…}`, kaputtes JSON 400). Der Smoke-Test in `.github/workflows/ci.yml` (Job `check`) prüft genau das.
- Entscheidung 001: Go-Modul `k3c` im Root; `engine/store` (Spielstände, Berichte), `engine/net` (HTTP), `cmd/`.
  Schichtgrenzen per `depguard` in `.golangci.yml`. Nur Standardbibliothek (`net/http`, `log/slog`, `encoding/json`).
- **Neu:** `GET /api/health` → 200 `{"ok":true}` (Entscheidung 🧑, 2026-09-30); Docker und `k3c-dev` prüfen damit.
- Konfiguration per Umgebung: `K3C_HTTP_PORT`, `K3C_HTTPS_PORT`, `K3C_DIST` (Vorgabe `dist`), `K3C_SAVES_DIR`
  (`saves`), `K3C_REPORTS_DIR` (`reports`), `K3C_CERTS_DIR` (`certs`); relative Pfade gelten ab dem Arbeitsverzeichnis.
- Dateien schreibt `engine/store` atomar (temporäre Datei, dann umbenennen): ein unterbrochenes Schreiben lässt den
  alten Stand heil.
- Der Online-Modus (WebSocket `/ws`) bleibt bis SP07/SP08 im Node-Server; `server/*.mjs` bleiben bis SP09.
