## Ziel

Das Slot-Register `data/assets.json` enthält alle Asset-Slots aus den Zuordnungstabellen und der Hörproben-Liste mit ihren bisherigen Zuordnungen als Präferenz 1; k3c-dev liest, durchsucht und schreibt Register und Asset-Katalog über ein Go-Paket und MCP-Tools.

## Kontext

- **Spec:** Sprint M10 (AC-01) und Ticket B-298 (hier B-298/AC-02 Reihenfolge im Register, AC-03 Ausschnitt gespeichert, AC-06 MCP-Tools). Begriffe: Asset-Slot, Slot-Register, Präferenz, Ausschnitt, Asset-Katalog (`docs/glossar.md`). „Slot“ allein ist der lokale Spieler, im Code daher `AssetSlot`/`assets`.
- **Quellen der Migration (einmalig):** Objekt-Tabellen in `docs/assets/zuordnung-objekte.md` und `zuordnung-welt.md` (Kopfzeile `| Objekt |`, Spalten Objekt, Herkunft, Pack, Datei/Frame, Stil, Lizenz, Status; Parser-Vorbild `src/tools/zuordnung.test.ts › objectRows`). Pack `grafik/<ordner>` → Datei `grafik/<ordner>/<erster Pfad in Backticks aus Datei/Frame>`, Pack `sprites/<ordner>` → Sheet aus `data/sprites.json`. Zeilen mit Status Lücke werden Asset-Slots ohne Zuordnung. Sound-Slots aus `public/audio/kandidaten.json` (`gruppe`, `datei` ohne Endung, `bus`) und dem Audio-Atlas `public/audio/atlas.json` (`sfx:coin`, `sfx:hit`, `sfx:warn`). Das Import-Skript liegt im Scratchpad und wird nicht eingecheckt; das Ergebnis sichert ein Test.
- **Format (Vorschlag, im `_comment` der Datei beschreiben):** `{ "_comment", "slots": [ { "id", "art": "grafik"|"sound", "kategorie", "beschreibung", "ziel"?: {w,h}, "bus"?: "sfx"|"music"|"ambient", "wahl": [ { "datei" (relativ zu `public/`), "sheet"? (ID aus `data/sprites.json`), "ausschnitt"?: {x,y,w,h}, "raster"?: {w,h} } ] } ] }`. Slot-IDs = Objekt-IDs der Tabellen (`farm`, `hub:1`, `mount:horse`, `bg:wald` …), Sound `sfx:<name>`, `music:<zustand>`. Kategorien: Grafik `figuren`, `gebaeude`, `umgebung`, `objekte`, `hud`; Sound `sfx`, `musik`, `ambient` (B-299).
- **Asset-Katalog:** Dateien unter `public/grafik/`, `public/sprites/`, `public/audio/`; Gruppe/Tag und Maße aus `public/grafik/index.json` (`pack`, `group`, `file`, `w`, `h`), Urheber und Lizenz je Pack aus `public/grafik/CREDITS.md`, `public/sprites/CREDITS.md`, `public/audio/README.md`. Suche nach Name, Pack, Tag, Lizenz (Teilstring, ohne Groß/Klein).
- **k3c-dev:** eigenes Go-Modul `tools/k3c-dev` (siehe `tools/k3c-dev/codemap.md`). Tools werden in `internal/mcpsrv/tools*.go` mit `add[In]` registriert; Namen `<bereich>_<verb>`, Beschreibung endet mit „Nutze es bei: … Statt: …“ (`tools_rules_test.go`). Schreibende Tools nehmen `checkout` (B-388) und arbeiten im Workspace-Root des Aufrufers. Atomares Schreiben: Vorbild `internal/planning/store.go › writeAtomic`.
- **Fallstrick:** Ein ungültiges Register darf nie überschrieben werden (laden scheitert → schreiben abgelehnt, Fehler nennen).
