## Ziel

Die Module `uikit` (HTTP-Oberflächen-API für den Browser-Dev-Betrieb: RPC, Ereignisstrom, Schutz), `claude` (Deep Link „In Claude öffnen“) und `winicon` (Fenster-Icon unter Windows) liegen in `k3c-kit`, ihre portierten Tests sind grün. Pflicht vor dem Start: `docs/standards/rust-werkzeuge.md` (› „Eine Aufruf-Tabelle je App“: dieselben Funktionen bedienen später Tauri-Commands und diese axum-UI-API). Stand: RU66.1–RU66.4. Go-Orakel (rund 774 Zeilen samt Tests):

### Vorentscheidungen (Claude, nach Leitfaden)

1. **Aufruf-Tabelle statt Reflexion:** Go ruft Methoden per `reflect` am Ziel-Typ. Rust: `pub type BoxFuture<T> = Pin<Box<dyn Future<Output = T> + Send>>;` und `pub type Method = Arc<dyn Fn(Vec<serde_json::Value>) -> BoxFuture<Result<serde_json::Value, String>> + Send + Sync>`; `pub struct Api { pub app: String, pub methods: HashMap<String, Method>, pub bus: Arc<Bus>, pub track: Option<Arc<dyn Fn(&str) -> Box<dyn FnOnce() + Send> + Send + Sync>> }`, `Api::router(self) -> axum::Router` mit `GET {PREFIX}events`, `POST {PREFIX}rpc/{method}`, `GET {PREFIX}` → 404 „Unbekannte Adresse“, alles hinter `guard`. Hilfe `pub fn args<T: DeserializeOwned>(raw: Vec<Value>) -> Result<T, String>` (Array → Tupel) mit den Fehlertexten von `decodeArgs`; `splitResult` entfällt (jede Methode liefert schon `Result`). Konstanten `PREFIX = "/api/dev/"`, `HEADER = "X-K3C-Dev"`, `MAX_RPC_BYTES = 1 << 20` (axum `DefaultBodyLimit`).
2. **Schutz:** `guard(app, router)` als axum-Middleware mit `host_allowed`, `same_site(&HeaderMap)`, `loopback(&SocketAddr)` (Bedienung mit `into_make_service_with_connect_info::<SocketAddr>()`), Kopf `X-K3C-Dev` für POST; Texte und Status wie Go. `reply`/`fail` wie Go.
3. **Ereignisse:** `Bus` über `tokio::sync::broadcast` mit Kapazität 1024 (`eventBuffer`), `publish(name, data: Vec<Value>)` kodiert wie Wails (erstes Argument, ohne Argument `null`), SSE über `axum::response::sse` mit Keep-Alive 20 s, Format Zeichen für Zeichen wie `events.go`. Für den Strom `tokio-stream = { version = "=0.1.19", features = ["sync"] }` (Version aus dem Spike-Lockfile, Tokio-Projekt, MIT; im Ergebnis melden). Beim Stoppen enden alle Ströme (z. B. `tokio::sync::watch` im Bus).
4. **`methods`:** `ts_methods(src: &str) -> Result<Vec<String>, String>` mit derselben Regex wie Go (`regex = "=1.13.2"`, Spike-Lockfile) und `check_methods(src: &str, methods: &HashSet<String>) -> Result<(), String>`. Der Go-Teil, der jede Methode am Go-Typ per Reflexion sucht, entfällt (die Tabelle ist die Quelle); im Ergebnis nennen. Welche TS-Datei die Apps künftig prüfen (`wails.ts` gibt es unter Tauri nicht), entscheiden RU70/RU69.
5. **`serve`:** `resolve_port` (Text wie Go), `async listen(env, port) -> Result<TcpListener, String>` mit Warten bis 10 s auf einen belegten Port (Muster `devrun.Listen`, `std::io::ErrorKind::AddrInUse`), `page_url(&TcpListener)`, `async serve(listener, router, shutdown: impl Future<Output = ()> + Send)`: beim Ende Ströme schließen, höchstens 2 s auf offene Anfragen warten.
6. **`claude`:** `MAX_PROMPT = 14000`, `link(prompt, folder) -> Result<String, String>` mit Go-Texten; Kodierung wie Go `url.Values.Encode` (Schlüssel sortiert: `folder` vor `q`; ungeschützt nur `A-Z a-z 0-9 - _ . ~`, Leerzeichen erst `+`, dann wie Go durch `%20` ersetzt, sonst `%XX` groß) als eigene kleine Funktion ohne Crate; Längengrenze 32.000. `open(prompt, folder)` startet `rundll32 url.dll,FileProtocolHandler <link>` mit `std::process::Command` **ohne** `proc` (Job-Objekt würde Claude Desktop mitreißen) und wartet in einem eigenen Thread.
7. **`winicon`:** Port, obwohl `tauri-build` das Icon vermutlich selbst einbettet (Leitfaden nennt das Modul; ob die Apps es brauchen, entscheiden RU70/RU69). `src/winicon/windows.rs` mit `#[allow(unsafe_code)]`, jede Stelle `// SAFETY:`; `windows`-Features ergänzen: `Win32_UI_WindowsAndMessaging`, `Win32_Foundation`, `Win32_System_Threading`. `set(png: &[u8])` (20 Versuche je 250 ms, `EnumWindows` mit Callback und Zustand über `LPARAM`, `WM_SETICON` groß und klein), `handle(png, px) -> isize` (`CreateIconFromResourceEx`, 0 bei Fehler); außerhalb von Windows leere Stubs wie `winicon_other.go`.

### Für den Hauptrechner
- RU69/RU70: `args` folgt serde, nicht `json.Unmarshal`: `null` für Nicht-`Option` und fehlende Struct-Felder ohne `#[serde(default)]` ergeben 400. `args()` muss im Aufruf selbst laufen (nicht in `spawn`), sonst 422 statt 400. Fehlertexte nach dem Doppelpunkt stammen von serde.
- RU69/RU70: `check_methods` prüft die Methoden nicht mehr am Typ (Tabelle ist die Quelle); welche TS-Datei geprüft wird, ist offen. `winicon::set` blockiert bis 5 s (eigener Thread). `Api::router` braucht `serve` oder `into_make_service_with_connect_info`.
- Strenger als Go: jedes `%` im Pfad, fehlender/doppelter `Host` und `Origin` ohne Schema ergeben 403; Rumpf über 1 MiB immer 400; `handle` verlangt PNG-Signatur und 33 Bytes.
- Weitere Abweichungen: voller SSE-Puffer verwirft die ältesten Ereignisse; `: halten` 20 s nach der letzten Zeile; Ereignisnamen mit CR/LF werden verworfen; JSON maskiert `<>&`/U+2028 nicht; Go-`ReadHeaderTimeout` (10 s) fehlt; Methodenpanik ergibt 500.
- Ungeprüft: `claude::open` mit gültigem Prompt, `winicon::set` am echten Fenster, Keep-Alive nach 20 s, 2-s-Abbruch hängender Anfragen, volle 10 s Portwartezeit, LAN-Gegenstelle über das Netz, Nicht-Windows-Stubs.
