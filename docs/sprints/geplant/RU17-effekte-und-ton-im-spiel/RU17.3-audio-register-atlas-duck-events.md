## Ziel

Das Slot-Register der Klänge (`register`), der Atlas (`atlas`), das Ducking (`duck`) und die Ereignis-Zuordnung (`events`) des Pakets `audio` stehen in Rust; die Ebitengine-Senke `sink` entfällt zugunsten von `k3c_platform::AudioOut`.

## Kontext

Leitfaden `docs/standards/rust-port.md` zuerst lesen. RU17.1 und RU17.2 haben `fx` geliefert; `audio` ist ein eigenes Modul, das nichts aus `fx` braucht.

**Quellen** in `native/k3c-game/audio/`: `register.go` (153, kein eigener Test; geprüft über `klang_test.go` in RU17.5), `atlas.go` (65, Test `atlas_test.go`), `duck.go` (52, getestet in `music_test.go`: `TestDuck`, kommt in RU17.4), `events.go` (127, Test `events_test.go`), `sink.go` (47, nicht portiert). Ziel: `rust/crates/k3c-game/src/audio/` mit `register.rs`, `atlas.rs`, `atlas_tests.rs`, `duck.rs`, `events.rs`, `events_tests.rs`. Diese Session legt das Modul `audio` an: `audio/mod.rs` (aus `audio.go`) bekommt nur die `mod`-Zeilen, den Inhalt von `audio.go` liefert RU17.5; `lib.rs` bekommt `pub mod audio;`. `view::Event`, `view::CueKind`, `view::Frame` aus `src/view`.

**register.** `ParseRegister(sounds, monarch)` baut aus den Dateien `data/sounds.json` und `data/monarch.json` das `Register` (`effects`, `music`: Slot → erste Präferenz; `mix: Mixing`; `skills`). In Rust liest `k3c_data::sounds` (`Sounds`, `SoundSlot`, `SoundChoice`, `SoundsMischung` vorhanden, Felder `mischung.effekte`, `musik`, `duck_pegel`, `duck_anstieg`, `duck_halten`) und `k3c_data::monarch` die Dateien schon: `parse_register` nimmt dieselben Eingänge als Text (Bytes) und parst mit `serde_json` wie Go (kleine private Strukturen `SoundsFile`, `MixingFile` wie in Go, damit Fehlermeldungen gleich bleiben), `load_register` entfällt zugunsten eines `load_register(fs: &dyn Fn(&str) -> Result<Vec<u8>, String>)` mit denselben Meldungstexten („❌ Slot-Register data/sounds.json: …“). `map[string]string` wird `BTreeMap<String, String>` (Go sortiert beim Laden, Reihenfolge ohne Folgen). `Mixing::default()` ist `default_mixing`; ein Register mit Null-Wert-`Mix` nimmt `default_mixing` (`mixing()`; Go vergleicht mit `Mixing{}`, in Rust `== Mixing::ZERO`). `skill_slot(id)` liefert den Slot oder `skill_fallback` („sfx:skill“).

**atlas.** `parse_atlas` (JSON mit Sprites: Start, Dauer je Slot; Ungültige verwirft Test `parse_atlas_dropsinvalidsprites`), `pick(exists)` wählt die erste vorhandene Datei in der Reihenfolge `ogg`, `mp3`, `wav` (`format_order`), `sprite_range(s, rate, total)` rechnet in ganzen PCM-Frames (`pcm_frame = 4`) und klemmt (`finite` prüft `NaN`/`Inf`). Der Go-Test `TestLoadBankDecodesAtlasAndSingles` und `TestLoadBankMissingFilesIsSilent`, `TestBusVolumesFromSettings` stehen in `atlas_test.go`, hängen aber an `bank`/`output`/`audio`: in dieser Session `#[ignore = "wartet auf RU17"]`, RU17.5 schaltet sie ein (Namen im Ergebnis).

**duck.** Reine Zahlenlogik (`duck_shape`, `duck_window`, `duck_gain(t, w)`, `extend_duck(w, t, s)`), `default_duck = { level: 0,35, attack: 0,15, hold: 1,2, release: 0,8 }`; keine eigene Testdatei, getestet in RU17.4.

**events.** `event_cues` ist die Tabelle Ereignis → `SoundCue { slot, global }` (15 Einträge; `BTreeMap` oder `match`), `cue_slot(CueKind)`, Pegel-Konstanten (`edge_gain`, …), `night_gain(phase)`, `attenuation(x, has_x, ears, global)` mit `Ear { center, span }`, `event_x(e, w) -> (f64, bool)`, `number`, `riding(p)`. `sim.World` und `sim.Player` kommen aus `k3c_sim::state`; Spielerzeiger werden Indizes.

**sink.** `sink.go` kapselt oto (`Sink`, `Player`, `openOto`). Das ersetzt `k3c_platform::AudioOut` (RU4.8, `open_audio()`); Rust bekommt keine `sink.rs`, die Tests der Go-Datei `output_test.go` nehmen `NullAudio` oder eine Test-Umsetzung von `AudioOut` in `audio/testutil.rs`. Das steht im Ergebnis als begründeter Wegfall.
