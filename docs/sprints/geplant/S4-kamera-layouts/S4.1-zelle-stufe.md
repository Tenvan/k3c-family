# S4.1 · Zuordnung Spieler → Stufe → Zelle und Zeichnen je Zelle

- **Status:** offen

## Ziel

Eine reine Funktion ordnet jeder Zelle des Layouts die Stufe ihres Spielers zu; `GameScene` zeichnet je Zelle die Welt dieser Stufe (Hintergrund, Parallax, Palette), und eine noch nicht geladene Stufe zeigt einen Platzhalter statt eines Absturzes.

## Kontext

- **Ist-Code:** `src/scenes/layout.ts` liefert mit `computeLayout(seats, hasPartner)` die Zellen (`Cell`: `x, y, w, h, kind: 'player' | 'partner', seat`). `src/scenes/GameScene.ts` hält genau eine Welt (`world_`), einen `WorldRenderer` (`renderer_`, `src/scenes/worldRenderer.ts`) und baut in `buildWorldView` Hintergrund (`drawBackground`, `drawRidge`, Parallax-Faktoren 0,3 und 0,6, Palette aus `world.biome.palette`) und Kameras (`layoutCameras`, eine Kamera je Zelle, `cam.setZoom(cell.h / GAME_HEIGHT)`, `startFollow` auf den Monarchen) für diese eine Welt auf. Alle Zellen zeigen also dieselbe Stufe.
- **Protokoll v3** (`docs/protocol.md`): `joined` und `seats` nennen je Platz `you[] = { slot, monarch, depth }` (`SlotSeat` in `src/online/clientProtocol.ts`). Das Gerät bekommt aber nur `level` und Zustand **einer** Stufe, der Stufe seines ersten Monarchen; Spieler anderer Stufen fehlen im Zustand (Entscheidung SP14, siehe `docs/sprints/erledigt/SP14-raum-auf-insel/README.md`: „mehrere Stufen gleichzeitig folgen mit B-106“). `RoomClient` (`src/online/clientConnection.ts`) hält darum nur `level: LevelInfo | null` und eine Frame-Liste.
- **Folge für diese Session:** Die Zuordnung (Zelle → Stufe) und die Zeichnung je Zelle werden gegen eine kleine Schnittstelle gebaut (Stufe → geladene Welt oder nichts). Mit dem heutigen Protokoll ist nur eine Stufe geladen, alle Zellen anderer Stufen zeigen den Platzhalter. Damit AC-04 (zwei Spieler in verschiedenen Stufen sichtbar) erreichbar wird, braucht das Protokoll Level und Zustand aller Stufen der lokalen Spieler. Das ist **nicht** Teil dieses Sprints (Nicht-Ziel „Protokoll“), Schritt 2 legt dafür ein Ticket an.
- Parallax und Palette stehen je Stufe in `world.biome.palette` (`sky`, `far`, `near`, `ground`); die Welt-Objekte zeichnet `WorldRenderer`.
- `src/scenes/` rechnet nichts (Test `src/scenes/noSim.test.ts`): die Zuordnung ist eine Auswahl aus Daten des Servers, keine Simulation.
- Vorschlag zur Umsetzung (Agent darf begründet abweichen): je Stufe eine eigene Ebene (`Phaser.GameObjects.Layer` oder Container-Gruppe) mit Hintergrund und `WorldRenderer`; jede Kamera blendet die Ebenen fremder Stufen per `cam.ignore(...)` aus. `GameScene.ts` hat 294 Zeilen, das Limit ist 400: neuer Code gehört in eine neue Datei, `buildWorldView`, `drawBackground` und `drawRidge` wandern dorthin.

Beim Wechsel einer Stufe wird nur deren Einheit neu gebaut.
