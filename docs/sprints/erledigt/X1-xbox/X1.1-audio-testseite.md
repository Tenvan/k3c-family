## Ziel

Die Gamepad-Testseite prüft Audio (AudioContext-Zustand vor und nach einer Geste, Abspielversuch ohne Geste, Dekodierung ogg/m4a/mp3/wav, Latenz), zeigt das Ergebnis an und schreibt es als Feld `audio` in den Bericht. Eine Testfunktion belegt die Auswertung, auch für `audio: null`.

## Kontext

- Die Seite besteht aus `gamepad-test.html` (Abschnitte `section` in der linken Spalte `.col`, Hilfsstile oben) und `src/tools/gamepadTest.ts` (333 Zeilen, Objekt `report`, `renderEnv()`, `pollPads()` mit `justPressed(i)`, `sendReport()` per `POST /api/report`). Sie kennt kein Audio (B-166 › Ausgangslage). Der Server (`engine/store/reports.go`) speichert jedes JSON-Objekt bis 256 KiB unverändert; der Server braucht keine Änderung. `report.version` bleibt `1` (Feld nur ergänzt).
- Die Datei darf nicht über 400 Zeilen wachsen: die Audio-Logik kommt in eine **neue Datei** `src/tools/audioProbe.ts`, `gamepadTest.ts` ruft sie nur auf (höchstens ca. 30 neue Zeilen dort). Funktionen höchstens 60 Zeilen.
- **Schnittstelle (fest, X1.3 liest das Feld so):** `report.audio` ist `null` (kein `AudioContext`) oder
  `{ contextState: { beforeGesture: string, afterFirstGesture: string | null }, gestures: { via: 'controller' | 'taste' | 'klick', state: string }[], autoplayWithoutGesture: 'gespielt' | 'blockiert' | 'fehler: <Name>', formats: { ogg: boolean, m4a: boolean, mp3: boolean, wav: boolean }, baseLatency: number | null, outputLatency: number | null }`.
  `state` ist `AudioContext.state` (`suspended`, `running`, `interrupted`, `closed`). `afterFirstGesture` ist `null`, solange keine Geste kam.
- **Ablauf:** Beim Laden der Seite (ohne Geste) `new AudioContext()` anlegen und `state` als `beforeGesture` merken, dazu `new Audio('audio-test/test.wav').play()` versuchen (`NotAllowedError` → `blockiert`, andere Fehler → `fehler: <Name>`, Erfolg → `gespielt`; sofort wieder anhalten). Dekodiertest: je Format die Datei per `fetch` laden und mit `ctx.decodeAudioData` dekodieren (`true`/`false`, ein Fehler stoppt die anderen Formate nicht; läuft auch bei `suspended`). Geste = Taste **A** (Button 0) auf einem Controller (`via: 'controller'`), irgendeine Tastaturtaste (`taste`) oder ein Klick auf den neuen Button „Audio entsperren und Testton“ (`klick`): jeweils `ctx.resume()`, danach `state` an `gestures` anhängen; die erste Geste setzt `afterFirstGesture`. Der Button spielt zusätzlich einen kurzen Ton (`test.wav` über den Context), damit 🧑 hört, ob etwas ankommt. Latenz: `ctx.baseLatency` und `ctx.outputLatency` beim Erstellen des Berichts lesen (`null`, wenn der Browser sie nicht liefert). Ob Controller-Tasten überhaupt als Geste zählen, ist die offene Messfrage von B-166; beide Wege werden deshalb getrennt festgehalten.
- **Testdateien** unter `public/audio-test/`: `test.wav`, `test.ogg` (Vorbis), `test.m4a` (AAC), `test.mp3`, je ca. 0,3 s Sinuston, mono, höchstens 20 KB, **selbst erzeugt** (kein Credit nötig). Auf diesem Rechner sind weder ffmpeg noch ein Encoder installiert (geprüft 2026-10-03). Weg: Python-Paket `imageio-ffmpeg` in einer temporären Umgebung außerhalb des Repos (`uvx --from imageio-ffmpeg python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"`), damit aus einem Sinuston (`-f lavfi -i sine=frequency=440:duration=0.3`) die vier Dateien erzeugen (`-c:a libvorbis`, `-c:a aac`, `-c:a libmp3lame`, `pcm_s16le`). Die Befehle stehen in `public/audio-test/README.md`. Gelingt das nicht, Session `blockiert` melden (nicht fremde Dateien laden).
- Der Go-Server liefert `dist/` aus; für `.ogg`, `.m4a` und `.mp3` kennt Go ohne Betriebssystem-Tabelle keinen Typ und rät aus dem Inhalt. Deshalb zählt nur das Ergebnis von `decodeAudioData` (typunabhängig), nicht der Content-Type.
- `public/` gehört sonst der Domäne CLI; die Ausnahme für `public/audio-test/` und für die Anleitung in `README.md` ergibt sich aus B-166 › Anforderungen (Testdateien unter `public/`).
- Regeln aus `CLAUDE.md` bleiben: `installPageChrome()` (Home-Button) bleibt unverändert, oben ca. 70 px frei, **B nicht belegen** (A als Geste ist erlaubt, B bleibt ohne Aktion), kein neues `*.html`, keine neue Abhängigkeit, kein `Math.random()`.
