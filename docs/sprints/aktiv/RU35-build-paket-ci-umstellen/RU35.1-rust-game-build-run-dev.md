## Ziel

Das Rust-Spiel kennt `rust:game:exe`, `rust:game:build`, `rust:game:run` und `rust:game:dev` wie jedes EXE-Projekt; `rust:game:build` legt ein vollständiges Paket nach `dist/k3c-rust/`.

## Kontext

Vorbild Go (nur lesen): `native/Taskfile.yml` › `game:build` (deps `game:exe`, `:gen:paper`), `game:dist` (intern: `cmd/sync` kopiert nur Geändertes; EXE, `public/audio`, `public/schrift`, `data` ohne `*.go`/`*.md`, `native/k3c-rig/assets`, Grafik laut `--assets`, `LIZENZEN.txt`), `game:exe` (`sources`/`generates`), `game` (Start). Heute in `rust/Taskfile.yml`: `build`, `test`, `lint`, `fmt`, `game:dist` (Release nach `dist/k3c-rust/` mit `data`, `public/grafik`, `rust/demo`, Start `demo.cmd`). Regeln: `CLAUDE.md` › Befehle („Dev ohne Neubau-Fenster“), EXE mit festem Pfad, kein `go run` fürs Spiel (Firewall).

**Vorentscheidungen:**

1. `rust:game:exe`: `cargo build --release -p k3c-game` mit `sources` (`rust/crates/**/*.rs`, `rust/crates/**/Cargo.toml`, `rust/Cargo.lock`) und `generates` (`rust/target/release/k3c-game.exe`).
2. `rust:game:build`: deps `game:exe` und `:gen:paper`, dann intern `game:dist` nach `PAKET` (in dieser Session `dist/k3c-rust/`). Inhalt wie das Go-Paket: EXE, `data` (ohne `*.go`, `*.md`), `public/audio`, `public/schrift` (falls vorhanden), `native/k3c-rig/assets` (das Rust-Spiel lädt die Rig-Teile relativ, `DEFAULT_RIG_DIR` in `rust/crates/k3c-game/src/art/library.rs`), **ganz** `public/grafik` (das Rust-Spiel hat keinen `--assets`-Filter; Filter wäre Rust-Code außerhalb des Bereichs). Kopieren weiter mit `native/k3c-game/cmd/sync` (wie heute in `rust:game:dist`; der Umzug des Werkzeugs gehört zu RU37). Demo-Treiber und `demo.cmd` entfallen aus dem Paket; der Unterbefehl `demo` bleibt in der EXE.
3. `LIZENZEN.txt`: Hat das Rust-Spiel eine Lizenz-Ausgabe (z. B. aus der Lizenz-Seite der Menüs, RU9/RU12), schreibt der Task sie ins Paket; sonst legt die Session ein Ticket im Sprint RU35 an (Projekt RSU, Rust-Crate-Lizenzen ins Paket) und das Ergebnis nennt das Paket „noch nicht weitergebbar“.
4. `rust:game:run`: `game:build`, dann `k3c-game.exe` aus dem Paket-Ordner starten (Arbeitsordner = Paket).
5. `rust:game:dev`: Debug-Bau (`cargo build -p k3c-game`), Start von `rust/target/debug/k3c-game.exe` mit Arbeitsordner Repo-Wurzel (findet `data/`, `public/grafik`, `native/k3c-rig/assets` direkt). Kein Neustart bei Änderungen: `engine/devrun` kennt nur Go, `cargo-watch` wäre ein neues Werkzeug; das steht in der `desc`.
6. `rust:game:dist` (alt) entfällt zugunsten von `rust:game:build`; Kopfkommentar von `rust/Taskfile.yml` anpassen.
