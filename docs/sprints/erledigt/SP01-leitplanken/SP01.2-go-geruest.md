## Ziel

Das Repo ist ein Go-Modul `k3c`. Die Balancing-Daten liegen in `data/` und sind die einzige Quelle für Client (Import)
und Server (`go:embed`). Die CI testet, lintet und baut Go für `windows/amd64` und `linux/arm64`.

## Kontext

- Zielbild: `docs/decisions/001-server-engine-go.md` › Entscheidung Punkt 3 (Aufbau im Repo).
- `go:embed` kann nur Dateien **im oder unter** dem Paket-Ordner einbetten. Deshalb wandern die Daten aus
  `src/data/` nach `data/` (Repo-Root) mit einer Go-Datei `data/embed.go` (Paket `data`).
- Importe der Daten heute (per `grep -rn "data/" src tests --include=*.ts` prüfen, Stand SP00):
  `src/scenes/sprites.ts`, `src/tools/spriteReference.ts`, `src/world/biome.ts`, `src/world/sim/data.ts`,
  `tests/sprites.test.ts`. Kommentare mit `src/data` in denselben Dateien anpassen.
- Doku mit `src/data`: `CLAUDE.md` (Struktur), `README.md` (Level anpassen), `docs/game-design.md`,
  `docs/arbeitsweise.md`, `docs/roadmap.md`, `public/sprites/CREDITS.md`. Nur den Pfad ändern (Grenzfall „Kleinstes“ für REG-, CLI- und Planungs-Dateien).
- `tsconfig.json` hat `include: ["src"]`; JSON-Importe außerhalb von `src` funktionieren mit `resolveJsonModule`.
  Meldet `tsc` trotzdem Fehler, `"data"` zu `include` hinzufügen.
- Lokal ist Go evtl. nicht installiert (Windows-PC des Entwicklers). Maßgeblich ist die CI.
- Schichtgrenzen für Go (`docs/arbeitsweise.md`): `engine/**` darf `k3c/cmd` nicht importieren; `engine/sim`,
  `engine/level` dürfen `k3c/engine/room`, `k3c/engine/net` nicht importieren. Die Pakete gibt es noch nicht,
  die Regeln werden trotzdem jetzt angelegt.

## Schritte

1. `git mv src/data data`. Alle Importe und Kommentare auf den neuen Pfad umstellen.
2. `npm run check` und `npm run build` müssen grün sein, bevor Go dazukommt.
3. `go mod init k3c` im Root mit der aktuellen stabilen Go-Version.
4. `data/embed.go`: `package data`, `//go:embed *.json biomes/*.json` auf `var Files embed.FS`, kurzer Kommentar.
5. `data/embed_test.go`: lädt jede eingebettete Datei, prüft `json.Valid`, erwartet mindestens die 8 JSON-Dateien
   im Root von `data/` und 3 Biome (Namen aus `ls data data/biomes`).
6. `.golangci.yml` (Format `version: "2"`): Linter `funlen` (lines 60, statements -1), `gocyclo` (min-complexity 15),
   `nestif` (min-complexity 4), `depguard` mit den Schichtregeln aus dem Kontext. Tests von `funlen` ausnehmen.
7. `ci.yml`: neuer Job `go` mit `actions/setup-go` (`go-version-file: go.mod`), `go test ./...`,
   `golangci/golangci-lint-action` (v2-Linie), `GOOS=windows GOARCH=amd64 go build ./...` und
   `GOOS=linux GOARCH=arm64 go build ./...`.
8. `package.json`: `"check:go": "go test ./... && golangci-lint run"` (für Rechner mit Go).
9. `CLAUDE.md` › Befehle: `npm run check:go` ergänzen; Struktur: `src/data/` → `data/` (Client + Server).
