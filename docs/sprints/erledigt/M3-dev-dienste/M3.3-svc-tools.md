## Ziel

Agenten starten, prüfen und stoppen die Dienste über `svc_status`, `svc_start`, `svc_stop` und `svc_restart`;
`k3c-dev` übernimmt beim Start laufende Dienste und stoppt beim Beenden die eigenen.

## Kontext

- Spec: `docs/backlog/archiv/B-067-dev-dienste.md` (MCP-Tools, Beenden, Beispiele, Fehlerfälle, AC-05, AC-07).
  Stand nach M3.2: `internal/services` mit Controller, Übernahme, Metriken, Log-Level-Zähler.
- Tools im Katalog `internal/mcpsrv/tools.go` (neue Datei `tools_services.go`); `Config` in `internal/mcpsrv/server.go`
  bekommt ein optionales Feld für den Controller (ohne Controller: Tools antworten `keine Dienste konfiguriert`).
  Annotations: `svc_status` `readOnlyHint`; `svc_start` `destructiveHint: false`; `svc_stop` und `svc_restart`
  `destructiveHint: true`.
- Antworten, eine Zeile je Dienst bzw. Befehl, z. B. `Vite · läuft · Port 5173 · PID 41232 · CPU 3,1 % · 480,0 MB ·
  2 h 13 min · Neustarts 0`; Log-Level als `Log 60 min: WARN 3 · ERROR 1` (nur mit `log`). Nach einem Befehl der neue
  Zustand und die Dauer bis gesund, bei Fehlern Grund und die letzten 10 Konsolenzeilen (`console.Store.Tail`).
  Unbekannter Dienst → Ablehnung mit allen Namen; `svc_stop` auf `übernommen` ohne `force` → Ablehnung mit Hinweis.
  Formatierung (`formatMs`, `formatBytes`, `formatUptime`) aus `internal/mcpsrv` wiederverwenden.
- `main.go`: Konfiguration laden (Fehler → Log und `svc_status` zeigt ihn, Server läuft trotzdem), `Adopt`, Controller
  an den Server, Zustandswechsel ins eigene Log; beim Beenden `StopAll` (nur eigene, rückwärts) vor `srv.Stop()`.
- `instructions.md`: Abschnitt Dienste – Agenten starten Dienste nie per Shell, sondern mit `svc_start`; Ausgabe über
  `console_tail <Dienst>`.
- `workbench_status` nennt je Dienst Zustand und Port in einer Zeile.

## Ergebnis

- **AC-04 geprüft:** `mcpsrv/tools_services_test.go` über MCP: `svc_start` → eine Zeile mit Zustand, PID, Laufzeit und
  Dauer, zweiter Start abgelehnt, `svc_status` eine Zeile je Dienst, `workbench_status` mit `Dienste: …`,
  `svc_restart`, `svc_stop`, unbekannter Dienst nennt die Namen; gescheiterter Start liefert Grund und die letzten
  Konsolenzeilen; übernommener Dienst nur mit `force`; ohne Controller bzw. mit kaputter `services.json` klare
  Meldung. Roundtrip-Test listet die vier Tools mit Annotations. Beenden stoppt nur eigene: `StopAll` lässt
  übernommene stehen (M3.2-Test) und `main.go` ruft es vor `srv.Stop()`.
- **AC-05 geprüft (von Hand, Agent, 2026-09-30):** gebaute EXE, über HTTP: `svc_start Vite` → `läuft` nach 2,1 s,
  `console_tail Vite` zeigt die Vite-Ausgabe, `svc_status` nach einer Messung `CPU 0,0 % · 133,8 MB` (der `node`-Prozess),
  `svc_stop Vite` → `gestoppt` in 7 ms, Port 5173 frei. k3c-dev **hart** beendet (`Stop-Process -Force`), während
  k3c-dev Vite führte: vorher lauschte `node` auf 5173, danach war der Port frei (Job Object). Fremder Vite über die
  Launch-Konfiguration des Browser-Panes gestartet: `Vite · übernommen · PID 15852 · CPU 2,3 % · 322,0 MB`,
  `svc_stop` ohne `force` abgelehnt, nach dem Ende von k3c-dev lief er weiter. Port-Prüfung mit
  `Get-NetTCPConnection` (`netstat | grep LISTEN` greift im deutschen Windows nicht).
- Grün: `npm run check:dev`, `npm run check`, `GOOS=linux GOARCH=arm64 go vet ./...`.
- **Abweichungen:** aus dem Handtest behoben: CPU und Speicher misst der Prozess am Port (sonst nur die Hülle
  `cmd.exe` von `npm.cmd`); `console_tail` entfernt ANSI-Farben (im Puffer bleiben sie für die Oberfläche);
  `svc_status` lässt CPU und Speicher weg, solange noch keine Messung da ist.
