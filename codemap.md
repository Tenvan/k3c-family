# Repository Atlas: K3C – Family Three Crowns

## Project Responsibility
Couch-Koop-Side-Scroller im Stil von Kingdom Two Crowns als natives Spiel für den PC: das Rust-Spiel `rust/crates/k3c-game` zeichnet, nimmt Eingaben und rechnet die Simulation in Rust (`k3c-sim`, `k3c-level`, `k3c-room`); Go ist seit RU71 restlos entfernt (Tag `go-werkzeuge-final`). Balancing-, Level- und Welten-Läufe startet das Studio über die EXE (`k3c-game sim`). Browser-Client, Spielserver und Online-Spiel sind entfernt (B-850, Sprint WR1). Balancing liegt als JSON in `data/` und ist die einzige Quelle. `tools/k3c-workbench` ist das Entwickler-Werkzeug (Tauri-App + MCP-Server `k3c-workbench`); `tools/k3c-studio` ist das Studio für Game- und Level-Designer (eigene EXE, MCP-Server `k3c-studio`: Welten, Hub, Assets, Balancing); Assets ändern nur die MCP-Tools `assets_*` des Studios; die Backends beider Apps samt gemeinsamem Code (`k3c-kit`) liegen im Cargo-Workspace `rust/tools/`. Grafik ist Papierschnitt (Entscheidung 005): Das Spiel lädt sie über die Gruppen-Indizes `public/grafik/<gruppe>/index.paper.json`, die Zuordnung steht in `data/paper.json`. `site/` ist die statische GitHub-Pages-Seite (Pages lädt nur `site/`, ohne Build).

## System Entry Points
- `rust/crates/k3c-game/`: Rust-Spiel (`task rust:game:run`, Paket `task build` nach `dist/k3c-game/`)
- `Taskfile.yml`: einziger Einstieg für Befehle (`task rust:game:run`, `task check`, `task check:dev` …)
- `package.json`, `tsconfig.json`, `vitest.config.ts`: Werkzeuge und Tests der Wurzel (`tests/`, `tools/paper`, TypeScript-CLIs)
- `rust/Cargo.toml` (Spiel) und `rust/tools/Cargo.toml` (Werkzeuge): zwei Cargo-Workspaces; `rust/Cargo.toml` plus `data/` markieren für die Apps die Repo-Wurzel
