- `revive` ist in golangci-lint enthalten. Regel-Konfiguration in golangci-lint v2:
  `linters.settings.revive.rules: [{ name: max-control-nesting, arguments: [4] }]`. Werden `rules` angegeben,
  laufen nur diese; das mit `golangci-lint run` auf dem Bestand prüfen (muss 0 Befunde bleiben).
- Go-Code gibt es nur in `data/`. Proben kommen in einen Wegwerf-Ordner `engine/probe/` und werden danach gelöscht.
- Werkzeuge lokal: Go 1.27, golangci-lint 2.14 (`requirements.md`). Entschieden (🧑, 2026-09-30): `nestif` wird ersetzt, nicht zusätzlich behalten.

## Ergebnis

- **AC-01 geprüft:** `.golangci.yml` aktiviert `revive` mit nur `max-control-nesting` (`arguments: [4]`), `nestif` ist
  entfernt; `config verify` und `golangci-lint run` grün, 0 Befunde. Proben in `engine/probe/probe.go`:
  A (`for` → 4× `if`, Tiefe 5) und C (`switch` → `for` → 3× `if`, Tiefe 5) melden „control flow nesting exceeds 4“,
  B (4× `if`, Tiefe 4) meldet nichts. B war eine exportierte Funktion ohne Doc-Kommentar und wurde nicht gemeldet,
  es läuft also wirklich nur diese eine `revive`-Regel. `engine/` gelöscht.
- **Befund `else if`:** `revive` zählt `else if` als eigene Ebene (Probe D gemeldet), Oxlint `max-depth` nicht
  (gleiche Struktur in TypeScript grün, eine Ebene tiefer rot). Go ist nur bei `else if`-Ketten um eine Ebene strenger;
  festgehalten in B-054 › Notizen, bewusst nicht umgebaut. *Korrektur L1.2:* jedes `else if` zählt eine Ebene, nicht
  nur eine insgesamt; `for range` zählt gar nicht (B-054 › Notizen, B-057).
- **AC-02 geprüft:** Kopfkommentar in `.golangci.yml` und `docs/arbeitsweise.md` › Werkzeuge nennen `revive` ›
  `max-control-nesting`; die Werkzeug-Zeile nennt zusätzlich, wo die Dateilänge geprüft wird.
- `npm run check` und `npm run check:go` enden mit Exit-Code 0.
- **Nebenbei:** Beim Aktivieren war `docs/sprints/aktiv/` leer und damit in Git nicht vorhanden; `git mv` benannte den
  Sprint-Ordner deshalb in `aktiv` um, korrigiert. Neu: `docs/sprints/aktiv/.gitkeep`, damit das nicht wieder passiert.
