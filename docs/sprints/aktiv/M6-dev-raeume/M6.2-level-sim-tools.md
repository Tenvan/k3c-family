## Ziel

k3c-dev rechnet Level und Simulationen selbst: `level_generate` zeigt ein Level als Textzeilen, `sim_run` führt einen deterministischen Lauf aus und fasst ihn zusammen.

## Kontext

- Das Go-Modul `tools/k3c-dev` (`k3c/tools/k3c-dev`) kennt das Hauptmodul `k3c` nicht. Einbinden: `require k3c v0.0.0` und `replace k3c => ../..` in `tools/k3c-dev/go.mod` (`go mod tidy`); `go.sum`/`vendor` nachziehen. Die CI-Jobs `k3c-dev` (Windows) checken das ganze Repo aus, das reicht. Schichtgrenze: `engine/*` importiert nichts aus `tools/`.
- API (nicht `engine/internal/...`, das ist für andere Module gesperrt): `level.LoadBiome(id)`, `level.Generate(b, seed) (Layout, error)`, `level.Validate`; `sim.CreateWorld(b, seed, sim.Options{CycleSpeed, Time}) (*World, error)`, `sim.AddPlayer(w)`, `sim.Step(w, []sim.PlayerCommand{{MoveX, Sprint, Pay}}, dt)`; Takt des Servers 30 Hz (`engine/room`, `TickHz = 30`), also `dt = 1.0/30` — vor dem Schreiben im Code nachsehen, wie `engine/room` `Step` aufruft, und dasselbe tun.
- Biome: `forest`, `cave`, `mine` (`data/biomes/*.json`). Golden-Daten: `testdata/golden/level-<biom>.json` (`{"biome":…, "levels":[{seed, biomeId, widthUnits, chunks, entities, …}]}`), nur lesen.
- Ereignisse der Simulation (`World.Events`, `engine/sim`): u. a. `wave`, `dawn`, `dusk`, `night`, `destroyed`, `playerDown`, `goldStolen`, `castleFallen`. Das Feld „Ende“ der Zusammenfassung: `castleFallen` → „Burg gefallen bei Tick N“, sonst „Ticks erreicht“. „Verluste“: Zahl der Events `destroyed` und `playerDown` getrennt ausweisen; beim Schreiben prüfen, was `destroyed` genau meint, und die Beschreibung des Tools danach richten.
- Adresse/Token spielen hier keine Rolle; die Tools laufen auch ohne Server (B-047 › Ausnahmefälle).
- Grenze (Entscheidung 🧑 2026-10-01): `ticks` höchstens 100 000, sonst Ablehnung mit der Grenze in der Meldung. Eingaben `inputs?`: kurze Liste von Segmenten `{player, fromTick, toTick, moveX, sprint, pay}` (ein Spieler reicht als Standard), Standard = ein Monarch ohne Eingaben.
