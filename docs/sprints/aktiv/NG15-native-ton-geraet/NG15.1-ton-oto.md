## Ziel

Das native Spiel spielt Ton über oto direkt; ein Fehler des Geräts schreibt eine Log-Zeile, macht stumm und lässt das Spiel weiterlaufen.

## Kontext

Spec: B-805 (Revision 2), AC-01. Heute: `native/k3c-game/audio` (`output.go`, `mix.go`, `music.go`) nutzt `ebiten/audio`; `audio.NewContext` hängt einen Hook ein, der Treiberfehler vor jedem Update zurückgibt (Ebitengine v2.10.6, `audio/audio.go:131`), damit endet `RunGame`. Nur „kein Gerät“ fällt unter Windows still auf ein Null-Gerät (oto `driver_windows.go:66`). Der Kontext entsteht nur in `audio` (`game/parts.go:54` ruft `audio.New`), `game` bleibt unverändert. oto v3.5.0 ist schon indirekt im Modul; mit direktem Import entfällt `// indirect` in `native/k3c-game/go.mod`, keine neue Version. Gerät kommt zurück → stumm bis zum Neustart. Opus wegen Treiber-Nebenläufigkeit.
