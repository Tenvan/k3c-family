## Ziel

Auf `main` liegt das Modul `tools/k3c-dev`, dessen `go run .` einen MCP-Server an `127.0.0.1:5180/mcp` startet. Der
Server hat einen Tool-Katalog, den Parameter-Hinweis, Zähler, das Aufruf-Log und `workbench_status`. `check:dev` und
der CI-Job laufen.

## Kontext

- Spec: `docs/backlog/archiv/B-046-dev-mcp.md` (Anforderungen › Modul, Transport, Katalog, Zähler und Aufruf-Log,
  `workbench_status`, Start in M1) und die Sprint-README (Regeln › Abhängigkeit und Ausnahmen).
- Heute gibt es Go nur im Hauptmodul `k3c` (`go.mod`, Go 1.27): `data/embed.go`, `tests/nesting_test.go`.
  `.golangci.yml` im Repo zeigt die Grenzen (`funlen` 60, `gocyclo` 15, `depguard`); `tools/k3c-dev/.golangci.yml`
  übernimmt `funlen` und `gocyclo` mit denselben Werten (ohne die `depguard`-Regeln für `engine/`).
- SDK: `github.com/modelcontextprotocol/go-sdk/mcp` v1.8.0. HTTP über `mcp.NewStreamableHTTPHandler`; Tools per
  `mcp.AddTool` mit typisierten Eingaben (Struct-Tags ergeben das Schema). Clients = aktive Sitzungen des Servers
  (vermutet: `Server.Sessions()`; beim Umsetzen in der SDK-Doku prüfen). Tests über `mcp.NewInMemoryTransports()`.
- Parameter-Hinweis: Das SDK lehnt unbekannte Felder mit einer Meldung ab, die `additional properties` enthält, nennt
  aber die gültigen nicht. Eine Middleware (Receiving-Middleware des Servers) hängt an genau diese Meldung
  `gültige Parameter: a, b` an; die Namen stammen aus den `json`-Tags der Eingabe-Structs, erfasst bei der Registrierung.
- Aufruf-Log: eine gemeinsame, fortlaufende Folge für Start- und End-Ereignisse (`startSeq`, `endSeq`), damit die
  Oberfläche später (M4) Start- und Endzeile eines Aufrufs verbinden kann. `ref` = 7 Hex-Zeichen, eindeutig im Ring.
- `workbench_status` zeigt in dieser Session Adresse, Laufzeit, Aufrufe, Fehler, Clients; Läufe (M1.2) und
  Log-Quellen (M1.3) ergänzen die folgenden Sessions.
