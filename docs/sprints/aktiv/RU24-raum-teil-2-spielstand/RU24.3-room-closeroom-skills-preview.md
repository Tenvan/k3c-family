Vorentscheidungen (Default, autonom, Claude, 2026-11-17; 🧑 kann widersprechen):
- `SkillError` (Go: Typ mit `Is(ErrBadRequest)`) wird eine Variante `Fehler::BadRequest { reason: String }`; der Text lautet `bad_request: <reason>` wie in Go; `errors.Is(err, ErrBadRequest)` wird `matches!(err, Fehler::BadRequest { .. })`. Der Code im Protokoll bleibt `bad_request`.
- `with_player(id, peer, slot, f func(*sim.World, *sim.Player) error)` wird eine Methode mit Abschluss `FnOnce(&mut World, usize) -> Result<(), Fehler>` (Spielerindex statt Zeiger).
- `Manager::delete_save(name, del: impl FnOnce() -> Result<(), Fehler>)` (Go: `del func() error`).
- `PreviewSource`/`PreviewOptions` und `BuildPreview`: Regex `^[a-z0-9-]{1,32}$` als Hand-Prüfung `valid_preview_biome`; `build_preview(o, &Data) -> Result<World, Fehler>` bekommt die Daten (Biome, Wertesatz) als Parameter statt der Paket-Variablen; sie ruft `create_world_with` (RU14.1), `validate_hub_data` (RU18.3), `check_chunk_count` (RU10) und `preview_set_site`/`preview_cycle`/`preview_hub_level` (RU14.1). `PreviewSiteKey(kind, x)` formatiert `x` wie Gos `%v`/`strconv` im Quelltext (Go lesen; Gleitkomma-Text von Rust `{}` entspricht dem kürzesten Text von `strconv.FormatFloat(v, 'f', -1, 64)`, nicht aber `%e`-Fällen; Test mit Werten wie `-3.5`, `120`, `0.1`).
- `CandidateError` wird eine Variante `Fehler::Candidate(String)` mit Text wie in Go; `candidate_world` ruft `parse_hub` und `validate_hub_data` (RU18.3), `clone_hub` entfällt.
- `chunk_at(lv, slot)` und `PreviewChunkObjects`/`PreviewChunkRuins` lesen das Level (`k3c_level::types::Layout`, `Chunk`, `PlannedObject`, `PlannedBuilding`, RU6); Reihenfolge der Ergebnisse wie in Go.
- `close_room` und `close_by_device` schließen synchron; der Spielstand wird vorher geschrieben (`save_now`, RU24.2).
