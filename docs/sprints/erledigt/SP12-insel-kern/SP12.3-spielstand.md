## Ziel

Auf `main` speichert ein neues Spielstand-Format (Version 2) eine `Island` mit Stufen, Hubs, Insel-Vorrat und der Stufe je Spieler und lädt sie wieder; ein alter Stand (Version 1, `Campaign`) wird gelesen und in eine Insel überführt. Das bisherige Format der `Campaign` (Version 1) bleibt für den Raum unverändert.

## Kontext

- Heute: `SaveGame` (Version 1, `save.go`): `CampaignID`, `Seed`, `Depth`, `UnlockedDepth`, `Time`, `SkillPoints`, `Hubs []HubSave` (je Tiefe: Burg-HP, Vorrat, Welle, Bauplätze, Truppen, entfernte Objekte), `Players []PlayerSave` (Gold). `Campaign.ToSave`, `ParseSave` (andere Versionen sind Fehler), `FromSave`. Der Raum (`engine/room/manager.go`) nutzt `sim.SaveVersion` und `ParseSave`; deshalb darf `SaveVersion`/`ParseSave` für `Campaign` unverändert bleiben.
- Neu: `IslandSave` (JSON-`version` 2): `CampaignID`, `Seed`, `Time`, `SkillPoints` (Summe der Stufen, bis B-118 den Pool je Insel ändert), `Stock` (Insel-Vorrat), `Stages []HubSave` (je Stufe), `Players []IslandPlayerSave` (`Index`, `Gold`, `Stage`). Funktionen `Island.ToSave(savedAt)`, `ParseIslandSave(raw)` (liest Version 1 **und** 2 und gibt eine `IslandSave` zurück; Version 1 wird überführt: `Depth` → Spieler in dieser Stufe, `Hubs` → Stufen, Vorräte der Hubs summiert (Ausnahme: wird ein Stand mit mehreren Hub-Vorräten überführt, ist die Summe der neue Insel-Vorrat, Annahme, im Ergebnis nennen)), `FromIslandSave(s, cycleSpeed) (*Island, error)`.
- Die Hubs speichert `hubSave(world, frische Welt)` wie bisher (Vergleichswelt frisch aus dem Seed: was fehlt, wurde entfernt); `applyHub` stellt sie wieder her.
- Annahme: Der Vorrat wird je Insel einmal gespeichert; `HubSave.Stock` der Stufen bleibt für Version 1 lesbar.
- Die Spielstände im Docker-Volume (`saves/`) sind Version 1; sie dürfen durch diesen Sprint **nicht** überschrieben oder verändert werden (der Raum nutzt weiter v1).
