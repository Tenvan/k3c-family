# K4.2 · Inselwechsel bestätigen, Protokollversion und Bytes je Tick

- **Status:** offen
- **Typ:** Umsetzung
- **Agent:** autonom
- **Umgebung:** offline
- **Branch:** k4/2-eingabe-version-bytes
- **Abhängig von:** K4.1
- **Tickets:** B-154, B-080
- **Kriterien:** AC-02, AC-04, AC-05, AC-06

## Ziel

Ein Gerät bestätigt den Inselwechsel (`bad_request` vor dem Sieg über den Endboss), die Protokollversion ist erhöht und ein älterer Client erhält `version`; die Bytes je Tick einer Bosswelle mit 4 Spielern sind gemessen und in `docs/protocol.md` notiert.

## Kontext

- **Eingang heute:** `engine/net/dispatch.go` (`handle` → `roomMessage` mit `addSlot`, `removeSlot`, `input`, `leave`, `dev`; alles andere → `room.ErrBadRequest`), `engine/net/protocol.go` (`inMsg`, `ProtocolVersion`, `codeVersion`), `engine/net/ws.go` (`handshake`: `m.V == ProtocolVersion`, sonst Fehler `version` und Schließen). Raum: `engine/room/actions.go` (`Room.Input` prüft Slot des Geräts; `own(id, peer)` liefert das Gerät nur für die aktuelle Verbindung), `engine/room/dev.go` als Muster für eine Raum-Methode je Nachricht. Client: `src/online/clientProtocol.ts` (`PROTOCOL_VERSION`, `ClientMessage`), `src/online/clientConnection.ts` (`RoomClient`; Datei ist mit über 400 Zeilen am Rand, Oxlint zählt ohne Leer- und Kommentarzeilen bis 400: wenn nötig die neue Sendefunktion klein halten).
- **Inselwechsel in der Sim:** entsteht in K2 (`engine/sim/`; Namen im Code gelten, Prüfung mit `grep -n "Travel\|Endboss\|Island" engine/sim/island*.go`). Regel laut `docs/rules/stufen.md` § 3 und B-154: frei erst nach dem Sieg über den Endboss; gewechselt wird erst, wenn alle **lebenden** Spieler am Punkt sind. Die Sim kennt die Regel; der Server ruft sie nur auf und prüft die Eingabe, er rechnet sie nicht nach. Fehlt im Code eine Funktion „Wechsel bestätigen“ oder eine Abfrage „freigegeben“: `Status: blockiert` und Ticket (Domäne SIM).
- **Entscheidungen dieser Session (Vorschläge der Planung, 🧑 bestätigt oder ändert sie mit der Spec-Freigabe; kein Beschluss):**
  - **Nachricht Gerät → Server:** `confirmIsland` mit `slot` (der bestätigende lokale Spieler); Name im Stil von `addSlot`/`removeSlot`. Slot fehlt oder gehört nicht zum Gerät → `bad_request`. Erfolg hat keine eigene Antwort; der nächste Zustand zeigt, wer am Punkt ist.
  - **Fehlerfälle nach B-154:** Bestätigung vor dem Sieg über den Endboss → `bad_request` (AC-02). Bestätigung eines einzelnen Spielers, während andere lebende Spieler fehlen, ist **kein** Fehler: die Eingabe wartet (Zustand zeigt „wartet auf …“ aus K4.1), erst wenn alle lebenden Spieler am Punkt sind, wechselt die Insel.
  - **Version:** `ProtocolVersion` um 1 gegenüber dem Stand nach W5 erhöhen (S2.1 setzt 4, W5.2 5, also hier 6; Code-Stand prüfen, die Reihenfolge der SRV-Bahn gilt). `hello` mit der vorigen Version → Fehler `version` und Schließen (Muster: bestehender Test in `engine/net/ws_test.go › TestHandschlagFalsch`).
- **Bytes je Tick:** Benchmark `BenchmarkIslandStep3Stages4Players` in `engine/sim/island_bench_test.go` (3 Stufen, 4 Spieler, Nacht; liefert `stateB/tick` und `stateB-p99/tick` als JSON des ganzen Zustands je Stufe und Tick, Aufruf `go test -bench Island -run '^$' ./engine/sim`). Für AC-05 braucht es eine **Bosswelle**: ein Boss-Szenario im Bench (Endboss ausgelöst, Warnkreis aktiv), erzeugt über die K2-Funktionen. Zusätzlich die Größe eines `delta` aus `deltaOf` (`engine/net/delta.go`) je Tick; die Messung als Test in `engine/net/` (neue Datei) mit Ausgabe per `t.Log`, ohne Grenzwert. Für den ganzen Zustand ist **keine Grenze beschlossen** (`docs/protocol.md` › Snapshot-Größe); beschlossen ist nur das Ereignis-Budget (Q08, ≤ 200 Byte je Tick und Client im Mittel, `TestEventsBudgetJeTick`). Neue Ereignis-Typen aus K2 und K3 zählen dazu: der Test muss grün bleiben, nicht gelockert werden. Die Messung ist ein Nachweis, kein Test mit Schwelle.
- Fallstricke: `ws_test.go` hat 390 Zeilen (neue Tests in neue Dateien); `Version` steht in `c2s-hello.json`, `s2c-welcome.json`, Tests mit `"v": …` (`ws_test.go`, `clientConnection.test.ts`): auf die Konstante umstellen. Ältere Dev-Aktionen und `forbidden` bleiben unverändert.
- Regeln: Protokolländerung nur in einer Protokoll-Session, beide Enden; Funktion ≤ 60 Zeilen, Datei ≤ 400; 2 Spieler je Gerät (Slots getrennt).
