## Ziel

Der Server läuft auf dem Raspberry Pi im Docker, startet nach einem Neustart von selbst, wird per `docker compose pull` aktualisiert und behält die Spielstände samt Sicherungen im Volume.

## Kontext

- Modell (B-042, 🧑 2026-10-02): **Pi 3 oder älter**. Das Image gibt es nur für `linux/amd64` und `linux/arm64` (`Dockerfile`); ein Pi 3 läuft damit nur mit einem **64-Bit-Betriebssystem** (Raspberry Pi OS Lite 64-bit). Ein Pi 2 oder älter ist damit nicht möglich. Ungeprüft: genaues Modell und RAM.
- `compose.yaml` zieht nach SP11.1 `ghcr.io/tenvan/k3c-family:latest`, Port 8080, Volume `k3c-data` unter `/data`, `restart: unless-stopped`.
- Diese Session führt 🧑 am Pi aus; ein Agent bereitet höchstens die Befehle vor und trägt Ergebnisse ein, die 🧑 nennt.
- Spielstand-Sicherungen: `saves/backups/<slot>/`, je Spielstand die letzten 5 (B-028, `GET /api/save/backups`).

## Schritte

1. Raspberry Pi OS Lite 64-bit installieren, SSH, feste IP oder Hostname im Heimnetz, Docker und das Compose-Plugin installieren (`docker --version`, `docker compose version`).
2. `compose.yaml` auf den Pi kopieren, `docker compose pull` und `docker compose up -d`. Im Browser `http://<pi>:8080/` öffnen, `GET /api/health` ist `ok`.
3. AC-01: Pi neu starten (`sudo reboot`), nach dem Hochfahren ist `http://<pi>:8080/` ohne Eingriff erreichbar.
4. AC-02: Einen neuen Tag `v*` veröffentlichen (oder `latest` neu bauen), auf dem Pi `docker compose pull && docker compose up -d`; `/api/health` oder die Seite zeigt die neue Version.
5. AC-03: Ein Spiel starten, speichern, Container neu erstellen (`docker compose down && docker compose up -d`): der Spielstand ist noch da; `GET /api/save/backups?slot=autosave` listet Sicherungen aus dem Volume.
6. Ergebnis eintragen (Modell, RAM, OS, Beobachtungen je Kriterium), Status `fertig`.
