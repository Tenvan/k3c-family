## Ziel

In `k3c-tui` lässt sich ein Raum ansehen, ein Gerät trennen, der Spielstand sichern und das Log verfolgen; die Aktionen wirken gegen den Server.

## Kontext

- Aus SP10.1: `cmd/k3c-tui/{client,model,view,main}.go`, Fehlertexte, Umgebung, `render`.
- Server (Sprint D1): `GET /api/status?room=CODE` → `{code,depth,tick,phase,day,gold[],troops{},enemies,castleHp,wave,devices[{id,connected,slots[]}]}`;
  `POST /api/status/disconnect?room=CODE&device=KENNUNG` → `{ok,room,device}` (404 unbekannt/nicht verbunden, 409 Kennung mehrdeutig);
  `POST /api/status/save?room=CODE` → `{ok,room,save,backup?}` (409 Raum geschlossen);
  `GET /api/status/log?since=<Byte-Cursor>&limit=<n>` → `{cursor,truncated,lines[]}`, die Zeilen sind rohe JSON-Zeilen von `slog` (`time`, `level`, `msg`, `ns`, weitere Felder); 404 „Log aus“ ohne Log-Datei.
- Ansichten (Zustandsautomat im Modell): `Übersicht` (SP10.1) → Enter auf einer Raumzeile → `Raum` (Zusammenfassung des Raums, Liste der Geräte, jede Sekunde neu) → `l` → `Log` (von überall `l`: Log des ganzen Servers). Esc/`q` geht eine Ansicht zurück, in der Übersicht beendet `q`.
- Tasten in `Raum`: Pfeile/`j` `k` wählen ein Gerät; `d` fragt „Gerät <Kennung> trennen? (y/n)“, nur `y` führt aus; `s` sichert den Spielstand sofort. Das Ergebnis jeder Aktion steht in der Statuszeile („Gerät aaaaaa getrennt“, „Spielstand gesichert“ oder die Fehlermeldung des Servers); die Anzeige läuft weiter.
- `Log`: beim Öffnen die letzten Zeilen holen: `since=0` liefert die ältesten, deshalb Cursor vorspulen oder die ersten Seiten verwerfen, bis nichts Neues kommt (höchstens ~20 Aufrufe), dann nur die letzten 500 Zeilen im Speicher behalten; danach jede Sekunde `since=<Cursor>` nachladen („folgen“). Darstellung: Zeit, Level farbig (ERROR rot, WARN gelb), `ns`, Meldung, weitere Felder als `k=v`; nicht lesbare Zeilen unverändert grau. `f` schaltet Folgen (Ende der Liste) ein/aus, Pfeile blättern. `truncated: true` → Hinweis „Log neu begonnen“. 404 „Log aus“ → Meldung statt Fehler.
- Der Server nennt Geräte nur mit der Kennung; die TUI sendet exakt diese zurück. Das Token wird nie angezeigt.
- Dateigrenze 400 Zeilen: neue Dateien `actions.go` (Aufrufe der POST-Wege), `logview.go` (Log-Zustand, Darstellung), `roomview.go` (Raumansicht); `model.go` bleibt klein.
