## Ziel

`tests/nesting_test.go` misst die Verschachtelungstiefe jeder Go-Funktion wie Oxlint `max-depth` und lässt
`go test ./...` bei Tiefe über 4 scheitern; `revive` ist aus `.golangci.yml` entfernt.

## Kontext

- Zählweise und Beispiele: `docs/backlog/B-057-go-tiefe-range.md` › Anforderungen, Beispiele, Ausnahme- und Fehlerfälle.
- Heute: `.golangci.yml` aktiviert `funlen`, `gocyclo`, `revive` (nur `max-control-nesting`, `arguments: [4]`),
  `depguard`; Kopfkommentar nennt `revive` und die Abweichungen (B-057).
- Go-Code gibt es nur in `data/` (`embed.go`, `embed_test.go`). Proben in einem Wegwerf-Ordner `engine/probe/`,
  danach löschen. Tests unter `data/`, `engine/`, `cmd/` scannen, dazu `tests/` selbst (die Prüfung ist Go-Code).
- Ein reines Test-Paket `tests` (nur `nesting_test.go`) ist erlaubt: `go build ./...`, `go vet`, Cross-Builds und
  `golangci-lint` bleiben grün (geprüft bei der Planung von L2).
- `tests/projectRules.test.ts` (TypeScript) zählt die Dateilänge von `.go`-Dateien bisher nur in `data/`, `engine/`,
  `cmd/` (Variable `goDirs`).
- Werkzeuge: Go 1.27, golangci-lint 2.14 (`requirements.md`). Stolperfalle: golangci-lint zeigt standardmäßig nur
  3 gleiche Meldungen; für Proben mit golangci-lint `--max-same-issues 0`.
- Umsetzungsskizze (kein Pflicht-Code): `filepath.WalkDir` über die Ordner, `parser.ParseFile`, pro `*ast.FuncDecl`
  und `*ast.FuncLit` eine rekursive Funktion `depth(node, level)`; `IfStmt` zählt +1, außer es ist das `Else` eines
  `IfStmt`; `ForStmt`, `RangeStmt`, `SwitchStmt`, `TypeSwitchStmt`, `SelectStmt` zählen +1; `FuncLit` beginnt bei 0.
  Die Prüfung selbst muss das Budget einhalten (Verschachtelung 4, Komplexität 15, Datei ≤ 300 Zeilen).

## Schritte

1. Sprint aktivieren: `git mv docs/sprints/geplant/L2-go-tiefe docs/sprints/aktiv/` (`aktiv/.gitkeep` sorgt dafür,
   dass der Ordner existiert), `Status: aktiv`, `Start-Commit` = `git rev-parse --short main`, Fahrplan anpassen.
2. `tests/nesting_test.go` (Paket `tests`) nach der Skizze; Meldung je Verstoß: `datei:zeile: Funktion X hat Tiefe N (> 4)`.
3. `tests/projectRules.test.ts`: `goDirs` um `tests` ergänzen.
4. `.golangci.yml`: `revive` samt Einstellung entfernen, Kopfkommentar auf die neue Prüfung umstellen.
5. `docs/arbeitsweise.md` › Werkzeuge: `revive` › `max-control-nesting` durch `tests/nesting_test.go` (Go-Tiefe) ersetzen.
6. Proben in `engine/probe/probe.go`, jeweils `go test ./tests/` ausführen:
   A `range` → 4× `if` → rot; B `range` → 3× `if` → grün; C flache `else if`-Kette mit 6 Zweigen → grün;
   D `for` → 4× `if` → rot; E `switch` → `for` → 3× `if` → rot; F `select` → 4× `if` → rot;
   G Funktionsliteral in Tiefe 3 mit 4× `if` darin → grün; H Datei mit Syntaxfehler → rot mit Datei und Parser-Fehler.
   `engine/` danach löschen.
7. `npm run check` und `npm run check:go` → Exit-Code 0.
