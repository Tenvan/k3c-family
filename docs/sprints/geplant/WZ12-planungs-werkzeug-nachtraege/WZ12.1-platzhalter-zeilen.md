## Ziel

`plan_create` für eine Session ersetzt Platzhalter-Zeilen ohne Datei (`–`, `– (Entwurf)`) in der Session-Tabelle durch die neue Session-Zeile, statt mit „The system cannot find the file specified“ abzubrechen.

## Kontext

Spec: B-436 und Sprint-README WZ12. Der Fehler entstand bei GEB1: Die Session-Tabelle des Entwurfs führte Zeilen mit Datei `– (Entwurf)`, das Tool hielt sie für bestehende Sessions und wollte die Datei öffnen. Die Tabellenlogik liegt in `tools/k3c-dev/internal/planning/tables.go` (`syncSessionRow`, `findTable`, `findRow`, `placeRow`, `removeRow`) und `create.go` (`createSession`); Tests nach Muster von `write_test.go`, `session_ids_test.go`.

Regel: Nur Zeilen **ohne Datei** sind Platzhalter (Datei-Zelle `–` oder `– (…)`). Eine Zeile mit Datei, die fehlt, bleibt ein Fehler (Verhalten wie heute). Welche Platzhalter-Zeile die neue Session ersetzt, entscheidet die Session-Nummer: Hat die Platzhalter-Zeile die Nummer der neuen Session, wird sie ersetzt; sonst bleibt sie stehen und die neue Zeile kommt dazu (Annahme, im Test festhalten). Tests laufen auf Kopien (`t.TempDir()`), nie auf dem echten `docs/`.
