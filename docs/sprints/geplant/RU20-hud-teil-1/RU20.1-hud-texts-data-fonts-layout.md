## Kontext

Leitfaden `docs/standards/rust-port.md` zuerst lesen. Der Sprint portiert **nur** die Dateien der Tabelle der README (`hud`, `state`, `data`, `values`, `layout`, `draw`, `paint`, `fonts`, `glyphs`, `icons`, `texts`, `hints`, `purse`, `drawstock`, `banner`, `radar`, dazu `drawglyph` und `keyline`, siehe README › Abweichung). Die Dateien von RU23 (`overlay`, `drawmenu`, `skillmenu`, `skilltext`, `story`, `drawstory`, `seekarte*`, `drawsea*`, `voyage`, `drawvoyage`, `drawworld`, `kampf`) legt dieser Sprint **nicht** an, auch nicht leer; was RU20-Dateien daraus brauchen, steht als Platzhalter in `hud/pending.rs` (Leitfaden § 7, ab RU20.4).

**Quellen** in `native/k3c-game/hud/`: `texts.go` (197, kein eigener Test; geprüft über `labels_test.go`, `values_test.go`), `data.go` (131, kein Test), `fonts.go` (107; Test `TestSchriftrollen` steht in `glyphs_test.go`, RU20.2), `layout.go` (193, Test `layout_test.go`: 7 Tests). Ziel: `rust/crates/k3c-game/src/hud/` mit `texts.rs`, `data.rs`, `fonts.rs`, `layout.rs`, `layout_tests.rs`. Diese Session legt das Modul `hud` an: `hud/mod.rs` (aus `hud.go`) bekommt nur die `mod`-Zeilen der RU20-Dateien, den Inhalt von `hud.go` liefert RU20.4; `lib.rs` bekommt `pub mod hud;`. `texts.rs` mit den zwei Textlisten (`textsDE`, `textsEN`, je um 55 Einträge) kann über 400 Zeilen kommen: dann `texts.rs` (Funktionen) und `texts_de.rs`, `texts_en.rs` (Tabellen) teilen.

**Go-Besonderheiten.** `texts`: `tr(lang, key)`, `has`, `name_of`, `tf(lang, key, kv...)`, `fill`, `lookup`, `str`. Go-`kv ...any` (Paare Name, Wert als `string`, `int` oder `float64`) wird `kv: &[(&str, Arg)]` mit `enum Arg { Str(String), Int(i64), Float(f64) }` (Vorentscheidung); die Textform einer Zahl muss `str(v)` aus `texts.go` entsprechen (Go `strconv`-Format lesen und nachbauen: Ganzzahl ohne Nachkommastellen, Gleitkomma wie dort). Ein unbekannter Platzhalter bleibt stehen; `tr` fällt auf Deutsch, dann auf den Schlüssel zurück. Tabellen als `static` Slices sortierter `(&str, &str)`-Paare mit Binärsuche oder `BTreeMap` (einmal gebaut, `OnceLock` erlaubt, `k3c-game` ist keine Sim-Crate); der Inhalt aller Texte wird Zeichen für Zeichen übernommen (Umlaute, `·`, Leerzeichen). `data.go` liest `monarch.json` (Skills und Linien in Dateireihenfolge, „Object.entries“), `economy.json` (`purse.maxGold`), `buildings.json` (Name, `bowRack`, `hammerRack`), `bosses` (Phasenzahl): in Rust über `k3c_data::monarch`, `economy`, `buildings`, `bosses`; die Reihenfolge der Skills liefert `k3c_data::ordered::Ordered` (`Entry { key, value }`). `read_json`-Fehler: Logzeile mit dem Emoji 💥 wie Go, Ergebnis leer. `fonts.rs`: `FontArt` (`Info`, `Side`), `FontRole { px, art, clr: [u8; 4] }`, die elf Rollen (`ROLE_PLAYER` … `ROLE_STORY`) und `min_font_px(seats, full_width, art)`, `scale_of(c: &Cell, cells)`, `luminance`, `contrast_ratio`, `rgb(hex, alpha)`, `font_px(role, cells)`; `ref_height = 1080,0`. `layout.rs` ist reine Geometrie (`Rect`, `Align`, `ItemId`, Anker-Tabelle `anchors`, `layout(in, area, free, k)`, `place`, `candidate`, `hits`, `gap = 8`, `row_h = 42`, `max_free = 4`) — Gleitkomma-Reihenfolge wie Go, `Placed` mit festen Arrays (`[Rect; ITEM_COUNT]`), keine `Vec` im Aufruf.

**Tests.** `layout_test.go` (7 Tests) ist rein, kein Zeichnen. `scale_of` (Go-Test `TestScaleOf`, in `layout_test.go`) braucht `view::Cell`/`Camera` (RU13/RU7: `src/view/cell.rs`).
