Heute: `data/islands.json` hat nur `islands` (Insel 1 mit `id`, `name`, `depths`, `depthScaling`, `plannedChunks`, `chunkCounts`); die Sim lädt sie einmal beim Start (`engine/sim/island_data.go` › `loadIslands`, `checkIsland`, globale Liste `islandDefs`). Der Spielstand (Version 7, `engine/sim/island_save.go`) speichert die Insel als Index `island` (Version 5, `island_save_v5.go`). Das Asset-Studio kennt schon einen Vorlauf für Welten (`engine/studio/app_world_files.go`: Welt-ID `^[a-z0-9][a-z0-9-]{0,31}$`, Standard-Welt = `data/islands.json`, weitere unter `data/worlds/`, Feld `name`; `app_island.go`: Insel anlegen und entfernen).

Zu entscheiden, mit Empfehlung:
1. **Format:** `{ "id", "name", "notes", "islands": [ … ] }`; `id` gleich dem Dateinamen, Muster wie im Studio; eine Insel hat die heutigen Felder. Unbekannte Felder werden abgelehnt, nicht still verworfen (`B-488 › Ausnahme- und Fehlerfälle`).
2. **Insel-IDs:** eindeutig je Welt, über Welten hinweg frei (jede Welt ist für sich vollständig); Muster wie die Welt-ID.
3. **Spielstand-Verweis:** Felder `world` (Welt-ID) und `islandId` statt Index `island`; alte Stände (bis Version 7) → Welt `standard`, Insel nach altem Index; unbekannte Welt oder Insel beim Laden → Fehler, die Datei bleibt unverändert.
4. **Laden im Spiel:** nur `standard` ist eingebettet (`data/embed.go`, `worlds/standard.json`); weitere Welten liest der Server nur im Dev-Mode (`K3C_DEV`) frisch von der Platte (`data/worlds/<id>.json`), damit eine im Studio gespeicherte Welt ohne Neubau startet.
5. **Git:** Eingecheckt ist nur `data/worlds/standard.json`; eigene Welten bleiben lokal (`.gitignore`: `data/worlds/*` mit Ausnahme `!data/worlds/standard.json`, umgesetzt in WZ18.2), bis 🧑 eine Welt einchecken will.
6. **Begriffe:** „Welt“ (Sammlung von Inseln, eine Welt-Datei) ist nicht `World` im Go-Code (dort eine Stufe) und nicht „in der Welt“ (Spielfläche). Empfehlung für den Code: Typ `WorldDef` in `engine/sim`; das Glossar grenzt die Bedeutungen ab.
