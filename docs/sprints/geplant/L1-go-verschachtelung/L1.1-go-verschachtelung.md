## Ziel

`.golangci.yml` prüft die Verschachtelungstiefe von Go-Code mit `revive` › `max-control-nesting` 4 statt mit
`nestif`, und die Doku nennt den neuen Linter.

## Kontext

- `.golangci.yml` (Format `version: "2"`) aktiviert heute `funlen`, `gocyclo`, `nestif`, `depguard`;
  `nestif` hat `min-complexity: 4`. Befund und Probe: `docs/backlog/B-054-go-verschachtelung.md`.
- `revive` ist in golangci-lint enthalten. Regel-Konfiguration in golangci-lint v2:
  `linters.settings.revive.rules: [{ name: max-control-nesting, arguments: [4] }]`. Werden `rules` angegeben,
  laufen nur diese; das mit `golangci-lint run` auf dem Bestand prüfen (muss 0 Befunde bleiben).
- Go-Code gibt es nur in `data/`. Proben kommen in einen Wegwerf-Ordner `engine/probe/` und werden danach gelöscht.
- Werkzeuge lokal: Go 1.27, golangci-lint 2.14 (`requirements.md`). Entschieden (🧑, 2026-09-30): `nestif` wird ersetzt, nicht zusätzlich behalten.

## Erlaubte Dateien

- `.golangci.yml`
- `docs/arbeitsweise.md` (nur die Zeile „Werkzeuge“ im Komplexitäts-Budget)
- `docs/sprints/aktiv/L1-go-verschachtelung/`, `docs/backlog/`

## Nicht-Ziele

Andere Linter oder Grenzen ändern; weitere `revive`-Regeln einschalten; Go-Code außerhalb der Proben schreiben.

## Schritte

1. `git rev-parse --short main` → in der Sprint-README als `Start-Commit` eintragen.
2. `.golangci.yml`: `revive` mit nur `max-control-nesting` (`arguments: [4]`) aktivieren; `nestif` samt Einstellung
   entfernen. Kopfkommentar anpassen.
3. `golangci-lint config verify` und `golangci-lint run` → Exit-Code 0, 0 Befunde.
4. Proben in `engine/probe/probe.go` (`package probe`), je eine Funktion:
   A `for` → `if` → `if` → `if` → `if` (Tiefe 5) → `golangci-lint run ./...` meldet `max-control-nesting`;
   B vier verschachtelte `if` (Tiefe 4) → keine Meldung; C `switch` → `for` → `if` → `if` → `if` (Tiefe 5) → Meldung.
   Zählt `else if` anders als erwartet, das Verhalten im Ergebnis festhalten. `engine/` danach löschen.
5. `docs/arbeitsweise.md` › Werkzeuge: `nestif` durch `revive` (`max-control-nesting`) ersetzen.
6. `npm run check` und `npm run check:go` → Exit-Code 0.
