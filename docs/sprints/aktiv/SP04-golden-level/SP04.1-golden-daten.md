## Ziel

`tests/golden.test.ts` erzeugt RNG-Folgen, Level und Simulationsläufe als JSON in `testdata/golden/`; `npm test`
schlägt fehl, sobald TS andere Daten liefert.

## Kontext

- Quellen (nur lesen): `src/core/rng.ts` (`hashSeed` FNV-1a über `charCodeAt`, `createRng` mulberry32 mit `next`,
  `int`, `pick`, `weighted`, `shuffle`), `src/world/levelGenerator.ts` (`generateLevel`, `validateLevel`),
  `src/world/biome.ts` (`BIOMES`: forest, cave, mine), `src/world/sim/world.ts` (`createWorld`, `addPlayer`, `step`),
  `src/world/sim/types.ts` (`PlayerCommand`). Snapshot wie in `src/world/sim/sim.test.ts`: Welt ohne `rng`, `biome`,
  `level`.
- Werkzeug: Vitest `expect(text).toMatchFileSnapshot(pfad)` schreibt fehlende Dateien und vergleicht sonst;
  `vitest run -u` schreibt neu. Keine neue Abhängigkeit.
- Zeilenenden: `core.autocrlf` ist unter Windows `true`, eine `.gitattributes` gibt es nicht. Prüfen, ob eine
  CRLF-Kopie der Daten den Vergleich bricht; nur dann `testdata/golden/** text eol=lf` in `.gitattributes`.
- Die Go-Seite (SP04.2, SP04.3, SP05, SP06) liest diese Dateien; Zahlen werden dort als `float64` verglichen, nicht als Text.

## Schritte

1. `Start-Commit` in der Sprint-README setzen (`git rev-parse --short main`), Branch anlegen.
2. `rng.json`: je Seed `hash`, 50× `next()`, 20× `int(0, 9)`, 10× `weighted({ a: 1, b: 3, c: 6 })`, `shuffle`
   von `[0..9]` und 10× `pick` aus `["x","y","z"]`, jeweils mit frischem Generator. Seeds mindestens: `""`, `"a"`,
   `"familie-2026"`, `"Käse🧀"`, `"Ärger über Öl"`, `"日本"`, `"👨‍👩‍👧‍👦"`, ein Text > 100 Zeichen.
3. `level-<biom>.json` je Biom: 20 Seeds (darunter `"Käse🧀"` und `"0"` … `"9"`), je Eintrag das `LevelLayout` von
   `generateLevel`; der Test prüft zusätzlich `validateLevel(...) = []`.
4. Simulationsläufe `sim-<name>.json` mit `dt = 1/30`, Snapshot bei Tick 0 und alle 30 Ticks; im File Biom, Seed,
   `cycleSpeed`, Spielerzahl, Eingabe-Folge (Segmente `{ ticks, commands }`) und Snapshots (ein Snapshot pro Zeile):
   - `forest-tag`: forest, Seed `golden-1`, 2 Spieler, `cycleSpeed` 1, 1800 Ticks. Der Test prüft: keine Gegner,
     kein Eintrag in `spawnQueue` (Grundlage für SP05).
   - `forest-nacht`: forest, Seed `golden-2`, 2 Spieler, `cycleSpeed` 20, 2700 Ticks (Dämmerung, Nacht mit Welle, Morgen).
   - `cave-aggression`: cave, Seed `Käse🧀`, 1 Spieler, `cycleSpeed` 100, 2700 Ticks (Aggression erreicht 100 → Welle).
   Eingaben: laufen, sprinten, bezahlen, stehen, je Spieler verschieden.
5. `package.json`: `"golden": "vitest run tests/golden.test.ts -u"`. Größe der Daten prüfen (Ziel < 5 MB gesamt,
   sonst Snapshot-Abstand erhöhen und in der Sprint-README vermerken).
6. Zeilenenden prüfen (Kontext). `npm run check` → grün. Ergebnis, lokal mergen.
