# M3.3 · MCP-Tools svc_*, Verdrahtung und Beenden

- **Status:** offen
- **Typ:** Umsetzung

- **Branch:** m3/3-svc-tools
- **Abhängig von:** M3.2
- **Tickets:** B-067

## Ziel

Agenten starten, prüfen und stoppen die Dienste über `svc_status`, `svc_start`, `svc_stop` und `svc_restart`;
`k3c-dev` übernimmt beim Start laufende Dienste und stoppt beim Beenden die eigenen.

## Kontext

- Spec: `docs/backlog/B-067-dev-dienste.md` (MCP-Tools, Beenden, Beispiele, Fehlerfälle, AC-05, AC-07).
  Stand nach M3.2: `internal/services` mit Controller, Übernahme, Metriken, Log-Level-Zähler.
- Tools im Katalog `internal/mcpsrv/tools.go` (neue Datei `tools_services.go`); `Config` in `internal/mcpsrv/server.go`
  bekommt ein optionales Feld für den Controller (ohne Controller: Tools antworten `keine Dienste konfiguriert`).
  Annotations: `svc_status` `readOnlyHint`; `svc_start` `destructiveHint: false`; `svc_stop` und `svc_restart`
  `destructiveHint: true`.
- Antworten, eine Zeile je Dienst bzw. Befehl, z. B. `Vite · läuft · Port 5173 · PID 41232 · CPU 3,1 % · 480,0 MB ·
  2 h 13 min · Neustarts 0`; Log-Level als `Log 60 min: WARN 3 · ERROR 1` (nur mit `log`). Nach einem Befehl der neue
  Zustand und die Dauer bis gesund, bei Fehlern Grund und die letzten 10 Konsolenzeilen (`console.Store.Tail`).
  Unbekannter Dienst → Ablehnung mit allen Namen; `svc_stop` auf `übernommen` ohne `force` → Ablehnung mit Hinweis.
  Formatierung (`formatMs`, `formatBytes`, `formatUptime`) aus `internal/mcpsrv` wiederverwenden.
- `main.go`: Konfiguration laden (Fehler → Log und `svc_status` zeigt ihn, Server läuft trotzdem), `Adopt`, Controller
  an den Server, Zustandswechsel ins eigene Log; beim Beenden `StopAll` (nur eigene, rückwärts) vor `srv.Stop()`.
- `instructions.md`: Abschnitt Dienste – Agenten starten Dienste nie per Shell, sondern mit `svc_start`; Ausgabe über
  `console_tail <Dienst>`.
- `workbench_status` nennt je Dienst Zustand und Port in einer Zeile.

## Schritte

1. `tools_services.go` mit den vier Tools, Katalog, `Config`-Feld, `workbench_status`.
2. `main.go`: laden, übernehmen, Controller übergeben, beim Beenden stoppen.
3. `instructions.md` und README ergänzen.
4. Tests: Roundtrip listet die Tools mit Annotations; Ablehnungen (unbekannter Dienst, `übernommen` ohne `force`);
   Antworttext bei Erfolg und Fehler (mit gestelltem Controller); `workbench_status`-Zeile.
5. Von Hand (B-067/AC-07): `go run .` in `tools/k3c-dev`, dann über HTTP (Wegwerf-Client wie in M1)
   `svc_start Vite` → `läuft`; `console_tail Vite` zeigt die Vite-Ausgabe; `svc_status` mit PID, CPU, Speicher;
   `svc_stop Vite` → `gestoppt`, Port 5173 danach frei (`netstat -ano | findstr :5173` leer). Dann `npm run dev` im
   Terminal starten, `k3c-dev` neu starten → `Vite · übernommen`; `svc_stop Vite` ohne `force` abgelehnt.
   Terminal-Vite danach von Hand beenden.
6. `npm run check:dev` und `npm run check` → grün. Ergebnis ausfüllen, lokal mergen.
