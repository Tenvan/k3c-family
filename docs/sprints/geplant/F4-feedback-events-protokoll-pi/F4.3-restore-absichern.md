# F4.3 · Restore nur mit Token, abgelehnte Zugriffe im Log

- **Status:** offen
- **Typ:** Umsetzung
- **Agent:** autonom

- **Abhängig von:** F4.2
- **Tickets:** B-143

## Ziel

`POST /api/save/restore` spielt einen Spielstand nur noch mit Token zurück; Lobby, WebSocket, Speichern und Berichte laufen ohne Geheimnis weiter; jede Ablehnung steht ohne Token im Log; die README beschreibt das Schutzmodell.

## Kontext

- Beschluss Q17 (`docs/fragenkatalog.md` › Beschlüsse): **Restore nur mit Token; Report und Client-Log nur Limits und Rotation (F4.2); kein Port-Forwarding (dokumentieren).** `POST /api/save` nennt der Beschluss nicht, es bleibt unverändert offen, ebenso `GET /api/save/backups`.
- **Auslegung:** „Token“ ist das vorhandene `K3C_STATUS_TOKEN` (`Config.StatusToken`, `cmd/k3c-server/main.go`), kein zweites Geheimnis. Ohne gesetztes Token ist Restore aus, wie `/api/status` (B-143 › Ausnahme- und Fehlerfälle). 🧑 bestätigt diese Lesart mit der Freigabe der Spec; passt sie nicht, Ticket anlegen und nichts weiter ändern.
- Ist-Stand: `restore` (`engine/net/status.go`) prüft nur die Methode. `authorized` (gleiche Datei) prüft alle Diagnose-Wege: ohne gesetztes Token 404, fehlendes/falsches Token 401 mit `WWW-Authenticate`, falsche Methode 405, Vergleich mit `subtle.ConstantTimeCompare`. `restore` nutzt `authorized(w, r, http.MethodPost)`.
- Log: `authorized` schreibt heute nichts. Für Restore gilt (B-143 › Anforderungen): jede Ablehnung genau ein Eintrag mit Pfad, Aufrufer und Grund (`ns` `save`), Zeit setzt `slog`. Aufrufer ist `r.RemoteAddr` (ohne Port); hinter einem Proxy ist das die Adresse des Proxys, `X-Forwarded-For` wird nicht ausgewertet (so in der README festhalten). Das Token und der Header `Authorization` erscheinen nie im Log. Die übrigen Diagnose-Wege bleiben, wie sie sind.
- Bestehender Test `TestSicherungenPerAPI` (`engine/net/status_test.go`) ruft Restore ohne Token auf (`statusServer(t, "")`) und erwartet für `GET` 405. Er wird an das neue Verhalten angepasst (Token setzen, Header mitschicken), nicht gelockert; die Pfad-Prüfungen (`../`, fehlende Sicherung → 400/404) bleiben mit gültigem Token erhalten. Testhelfer: `statusServer`, `get` (`status_test.go`), `diagToken` (`status_actions_test.go`), Log-Mitschnitt wie in `status_log_test.go`.
- Kein Aufrufer von Restore im Client (`src/`); genutzt wird es nur von Hand laut README. Das Beispiel dort bekommt den Header.
- Regeln: Standardbibliothek, Token nie in Logs, Spielbetrieb ohne Token bleibt möglich. Funktion ≤ 60 Zeilen, Datei ≤ 400.
