## Ziel

Eine getestete reine Funktion `mountPose` in `src/scenes/mountPose.ts` bestimmt aus Snapshot-Werten (`vx`, `facing`), dem aktuellen Reittier-Frame und den Daten (`data/sprites.json › mounts`, `riderWaist`, `data/monarch.json › mount`), welches Reittier mit welcher Animation und Bildrate gezeichnet wird und wo der Reiter sitzt; ein unbekannter Schlüssel ergibt den Rückfall auf die bisherige Figur. Noch nichts im Spiel sichtbar (S7.2).

## Kontext

- Beschluss Q23 (`docs/fragenkatalog.md` › Beschlüsse): Reittiere von Anfang an, jeder Monarch reitet ein Standard-Reittier; Sim in S1 (B-152), Darstellung hier (B-173). Regel: `docs/rules/monarch.md` § 7 „Reittier“ (Tierart Pferd, Sprite `horse`, Faktoren 1,0; Vorschläge aus F1.3, bestätigt in F1.4). Die Darstellung liest den Schlüssel **nur aus den Daten**, nie aus dem Code; ändert F1.4 das Tier, ändert sich nur `data/monarch.json`.
- **Daten nach S1.3 (vor dem Start im Code prüfen, Namen im Code gelten):** `data/monarch.json › mount` = `{ "id": "horse", "sprite": "horse", "speedFactor": 1.0, "sprintFactor": 1.0 }` (Vorschlag aus S1.3). Fehlt `mount` auf `develop` oder heißt der Sprite-Schlüssel anders als `sprite`: `Status: blockiert` (`docs/arbeitsweise.md` › Wenn etwas nicht passt), nicht raten. Der Client liest `data/monarch.json` über `src/model/data.ts` (`export const MONARCH = monarchJson;`, Typ aus dem JSON abgeleitet, enthält damit `mount` ohne Codeänderung). Weitere Werte dort: `base.speed` 5, `sprintMultiplier` 1.8, `acceleration` 8; Presets haben eigene `speed` (Dieb 5.5).
- **Snapshot:** `src/model/types.ts › Player` hat `id`, `index`, `x`, `vx`, `facing` (1 | −1), `respawnIn`, `hp`, `gold` … Es gibt **kein** Sprint-Feld und keine Klasse im Snapshot; Sprint erkennt man nur an `|vx|`. Der Client rechnet nichts (`CLAUDE.md`, `src/scenes/noSim.test.ts`): Die Funktion leitet nur Darstellung aus Snapshot und Daten ab, sie verändert keinen Zustand und integriert keine Position.
- **Sprite-Daten:** `data/sprites.json` hat `sheets` (je Sheet `frameWidth`, `frameHeight`, `originX`, `originY` = Fußpunkt 0..1, `height` = Figurhöhe in Frame-Pixeln, `scale`, `anims.{idle,run,attack}.{frames,fps}`), `players` (4 Specs: `medieval-king`, `medieval-king-2`, getönt), `mounts` (13 Tiere: `label`, `sheet`, `scale`, optional `tint`, `saddle.{idle,run}` = Sattelpunkt je Frame in Frame-Pixeln, Blick nach rechts) und `riderWaist` (0.6 = Anteil der Figurhöhe, der über dem Sattel sichtbar ist). Beispiel `horse`: Sheet `horse` (100×65, Origin 0.55/0.969, `idle` 1 Frame, `run` 11 Frames bei 14 fps), Reittier-`scale` 2.2. `tests/sprites.test.ts` prüft schon: jedes Reittier hat ein Sheet und je Frame einen Sattelpunkt.
- **Vorbild der Rechnung:** `src/tools/spriteReference.ts` › `draw` (Zeilen ~292–314) zeichnet Reittier plus Oberkörper des Reiters auf Canvas: Reittier-Zoom = `mount.scale`, Reiter-Zoom = `sheet.scale × (spec.scale ?? 1)`; Hüfte des Reiters (`waist = originY·frameHeight − height·(1 − riderWaist)`, Frame-Pixel von oben) auf den Sattelpunkt. Das ist eine Referenzseite (Domäne PLAT), sie wird **nicht** geändert und nicht importiert.
- **Heutiger Monarch:** `src/scenes/worldRenderer.ts` › `createPlayer`/`updatePlayer` (einzelnes Sprite aus `PLAYER_SPRITES[p.index % 4]`, `face(sprite, p.facing)`, `playAnim(sprite, |vx| > 0.05 ? 'run' : 'idle')`). Typen und Helfer: `src/scenes/sprites.ts` (`SheetData`, `SpriteSpec`, `SHEETS`, `PLAYER_SPRITES`; der Typ für `mounts` fehlt dort noch). Nach S4 kann das Zeichnen der Monarchen in einer anderen Datei liegen (`grep -rn "PLAYER_SPRITES" src/scenes`); für diese Session egal, sie fasst den Renderer nicht an.
- **Entscheidungen dieser Session (Vorschläge der Planung, 🧑 bestätigt mit der Freigabe):**
  - Signatur: `mountPose(p: { vx: number; facing: 1 | -1 }, frame: number, ctx: MountContext): MountPose | null`; `null` = Rückfall auf die bisherige Figur. `MountContext` = `{ key: string | undefined; rider: SpriteSpec; refSpeed: number; mounts; sheets; riderWaist }`, damit Tests eigene Mini-Daten übergeben. `MountPose` = `{ key, sheet, scale, tint?, anim: 'idle' | 'run', timeScale, flip, saddleFrame, rider: { x, y, originX, originY, cropHeight, scale }, top }` (Pixel relativ zum Fußpunkt des Monarchen).
  - **Stehen, Laufen, Sprint:** `|vx| ≤ 0.05` (heutige Schwelle aus `updatePlayer`) → `idle`, `timeScale` 1; sonst `run` mit `timeScale = clamp(|vx| / refSpeed, 0.5, 2.5)`. `refSpeed = MONARCH.base.speed × MONARCH.mount.speedFactor` (setzt S7.2 aus den Daten). Damit läuft das Reittier beim Laufen mit `timeScale` ≈ 1 und beim Sprint (×1,8) sichtbar schneller, ohne Sprint-Feld im Protokoll (B-173 › Beispiele: „beim Sprint schneller animiert“). Grenzen 0.5 und 2.5 als Konstanten in `mountPose.ts`.
  - **Spiegelung:** `flip = facing < 0`; gespiegelt wird um den Fußpunkt: `rider.x` wechselt das Vorzeichen, `rider.originX` wird `1 − originX` (wie `face()` in `sprites.ts`).
  - **Sattelpunkt:** `saddle = mount.saddle[anim][frame]`; fehlt der Frame (Index außerhalb), nimm `frame % Länge`; fehlt die Animation, nimm `saddle.idle[0]`; fehlt beides → `null` (kein Absturz). `sx = (saddle[0] − ms.originX·ms.frameWidth)·mount.scale`, `sy = (saddle[1] − ms.originY·ms.frameHeight)·mount.scale` (`ms` = Sheet des Reittiers).
  - **Reiter:** Oberkörper, Hüfte auf dem Sattelpunkt: `cropHeight = waist` (Frame-Pixel von oben), `rider.originY = waist / rs.frameHeight`, `rider.originX = rs.originX`, Position `(sx, sy)`, `rider.scale = rs.scale × (rider.scale ?? 1)`. `top = sy − rs.height · riderWaist · rider.scale` (Oberkante für Goldbeutel und HP-Balken).
  - Zeichenreihenfolge (B-173 „Tiefe“): Reiter immer über dem Reittier; das setzt S7.2 um, die Funktion liefert nur Werte.
  - Typ `MountData` (`label`, `sheet`, `scale`, `tint?`, `saddle`) und Exporte `MOUNTS`, `RIDER_WAIST` in `src/scenes/sprites.ts` (die Datei importiert `data/sprites.json` schon). `sprites.ts` importiert Phaser; `mountPose.ts` nimmt daraus nur Typen (`import type`), die Werte kommen über `ctx`.
