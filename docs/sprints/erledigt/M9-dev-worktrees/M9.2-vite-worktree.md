## Ziel

Der Vite-Dev-Server eines Worktrees unter `.claude/worktrees/` lädt eine geänderte Datei unter `src/` neu; der Dev-Server der Repo-Wurzel beobachtet die Worktrees weiterhin nicht.

## Kontext

- **Ursache:** `vite.config.ts` setzt `server.watch.ignored` auf `['**/.claude/**', '**/.omc/**', …]` (Kommentar: Worktrees haben zehntausende Dateien). Das Glob passt auf **absolute** Pfade; liegt die Vite-Wurzel selbst unter `.claude/worktrees/<name>/`, passt `**/.claude/**` auf jede Datei des Worktrees, Vite sieht keine Änderung und liefert alten Code (B-275 › Ausgangslage).
- **Lösung (Vorschlag):** `.claude` (und die übrigen Einträge, soweit sie dasselbe Problem haben) nur relativ zur eigenen Wurzel ignorieren, z. B. mit absolutem Pfad aus dem Ordner der Konfiguration (`path.join(<Wurzel>, '.claude')`) oder einem Glob ohne führendes `**/`. chokidar (Vite) nimmt Globs, absolute Pfade und Funktionen; im Code prüfen, was die installierte Vite-Version akzeptiert.
- **Tests:** `test.exclude` enthält `'.claude/**'` (relativ zur Wurzel); prüfen, ob die Tests im Worktree damit weiter laufen (`task test` im Worktree zählt dieselben Dateien wie in der Wurzel), nur bei Bedarf ändern.
- **Domänen-Ausnahme:** `vite.config.ts` gehört INF (B-275 › Regeln und Einschränkungen); M9 ist SRV. Diese Session ändert nur `vite.config.ts` (Sprint-README › Regeln und Einschränkungen).
- **Dienste im Worktree:** Vite eines Worktrees läuft auf eigenem Port (Versatz 10, 20 …, z. B. 5183; `svc_status`). Nie Port 5173 der Wurzel ansprechen. Dienste nur über `svc_start`/`svc_stop`; bedient k3c-dev nicht diesen Worktree (`workbench_status`, siehe M9.1), Vite mit `task dev` in einer Hintergrund-Shell starten und am Ende beenden. Firewall-Regel: Proben nur auf Loopback (`127.0.0.1`).

## Ergebnis

Stand 2026-10-07, autonomer Lauf auf `sprint/m9` (Auftrag: kein eigener Branch, keine Dienste, kein Port). Die Domänen-Ausnahme INF ist bestätigt (Sprint-README › Freigabe). Geändert ist nur `vite.config.ts`.

**Umsetzung:** `server.watch.ignored` nimmt statt `'**/.claude/**'` die Funktion `inClaudeDir`: Sie ignoriert eine Datei nur, wenn sie unter `<Wurzel der Konfiguration>/.claude` liegt (`path.relative`, unter Windows ohne Groß-/Kleinschreibung). chokidar 3 (Vite 8.3.1) nimmt Funktionen in `ignored` (`AnymatchFn`). Die übrigen Globs (`**/.omc/**`, `**/logs/**` …) bleiben: Der Pfad `.claude/worktrees/<name>` enthält keinen dieser Ordner. `test.exclude` (`'.claude/**'`, relativ zur Wurzel) bleibt unverändert.

**Beobachtung ohne Port:** Statt `task dev` + `curl` (Schritte 2 und 4) startet ein Probe-Skript Vite im `middlewareMode` (`hmr: false`, `ws: false`, kein Listen) mit der echten `vite.config.ts` dieses Worktrees (`.claude/worktrees/sprint-m9`), holt `src/__probe_m92.ts` über `transformRequest`, ändert die Datei, wartet 2,5 s und holt sie erneut. Gleichzeitig legt es `.claude/worktrees/__probe_m92/src/p.ts` (Worktree im eigenen `.claude/`, wie aus Sicht der Repo-Wurzel) an und zählt die Watcher-Ereignisse. Beide Probe-Dateien danach gelöscht.

| | vorher (`'**/.claude/**'`) | nachher (`inClaudeDir`) |
|---|---|---|
| `src/__probe_m92.ts` nach Änderung | `ALT` (alter Inhalt), kein Watcher-Ereignis | `NEU`, Ereignis `change` |
| Datei unter eigenem `.claude/worktrees/` | kein Ereignis | kein Ereignis (1 Ereignis gesamt, nur `src/`) |
