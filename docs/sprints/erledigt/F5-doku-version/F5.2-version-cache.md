## Ziel

`GET /api/health` meldet zusätzlich die Server-Version, der Client kennt seine Build-Version, die Fußzeile der Landingpage zeigt beide und hebt Abweichung hervor, und ein Test belegt die Cache-Header.

## Kontext

- Server-Version: `var version = "dev"` in `cmd/k3c-server/main.go`, gesetzt per `-ldflags "-X main.version=…"` (`Dockerfile`, `.github/workflows/release.yml`); sie liegt als `Config.Version` im Handler (`engine/net/handler.go`) und erscheint nur in `GET /api/status` (`engine/net/status.go`, Token-geschützt).
- `GET /api/health` (`engine/net/handler.go`, Funktion `health`) liefert `{"ok":true}`; die Landingpage prüft damit in `src/landing/serverCheck.ts` (`serverReachable`) nur `ok === true`. Das Feld `version` kommt **zusätzlich**, `ok` bleibt, Docker-Healthcheck und CI (`curl /api/health`, `-health`) bleiben kompatibel.
- Client-Version: Vite `define` in `vite.config.ts` (`__K3C_VERSION__`, aus Umgebungsvariable `VERSION`, sonst `dev`); der Docker-Schritt `web` im `Dockerfile` bekommt `ARG VERSION=dev` und gibt es an den Build weiter (`ENV VERSION=$VERSION`); die globale Deklaration steht in `src/env.d.ts` (neu, `tsconfig.json` schließt `src` ein).
- Fußzeile: `index.html` (Block `<footer class="hints">`) bekommt ein Element für die Version; `src/landing/landing.ts` ruft die Version beim Start ab (nicht blockierend, Timeout wie `serverReachable`) und setzt den Text über eine kleine reine Funktion (Vorschlag: `src/landing/version.ts`, Test `version.test.ts`).
- Cache: `engine/net/static.go` setzt für `.html` `Cache-Control: no-cache`, sonst `public, max-age=31536000, immutable`. Ein Test dafür existiert nicht (Suche in `engine/net/*_test.go`).
- Domänen-Ausnahme: Die Freigabe der Sprint-Spec erlaubt die Änderungen an `engine/net/handler.go` und `Dockerfile` (Sprint-README › Regeln und Einschränkungen).
