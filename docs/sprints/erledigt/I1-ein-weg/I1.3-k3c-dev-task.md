# I1.3 · k3c-dev führt Prüfungen über `task` aus

- **Status:** fertig
- **Typ:** Umsetzung

- **Umgebung:** live
- **Branch:** i1/3-k3c-dev-task

## Ziel

`check_run` und die Dienste in k3c-dev starten die Prüfungen über `task`, nicht über `npm`; im Werkzeug steht kein `npm run` mehr.

## Kontext

- `tools/k3c-dev` ist ein eigenes Go-Modul (Entscheidung 001). Der Prüfkatalog (`check_run`, Ziele `npm:check`, `npm:test` …) liegt in `internal/mcpsrv` (`tools.go`, `instructions.md`), Dienste in `services.json`, Anzeigen in `app_logs_test.go` und im Frontend (`frontend/src/api/mock.ts`, `mockLogFiles.ts`).
- Die Ziele werden zu `task:check`, `task:test`, `task:check:go`, `task:check:dev` …; die bisherigen Namen `npm:*` entfallen. Der Aufruf ist `task <name>` (unter Windows `task.exe`; Meldung, wenn `task` nicht gefunden wird, wie bisher bei `npm.cmd`).
- Das Frontend-Bundle `frontend/dist/` wird beim Bauen erzeugt (`task dev:frontend`); `task check:dev` baut es, danach `go test` und `golangci-lint`.

## Erlaubte Dateien

- `tools/k3c-dev/**` (nur Prüfkatalog, Dienste, Tests, Mock, Anleitungstext)
- `docs/sprints/`, `docs/backlog/`

## Nicht-Ziele

Neue Tools oder Dienste; Änderungen an der Oberfläche über die Namen der Ziele hinaus.

## Schritte

1. Branch anlegen, `Status: in Arbeit`.
2. Katalog, Anleitung, Dienste, Tests und Mock von `npm:…` auf `task:…` umstellen (Go-Tests in `internal/mcpsrv` und `app_logs_test.go` anpassen).
3. `grep -rn "npm run\|npm:" tools/k3c-dev` (ohne `node_modules/`, `frontend/dist/`) → leer.
4. `task check:dev` → grün; `task check`, `task check:go` → grün. Ergebnis, lokal mergen.

## Ergebnis

- **AC-04** umgesetzt, geprüft: `grep -rn "npm run" .` (Ausnahmen wie in der Sprint-README, `docs/sprints/` zitiert den Befehl selbst) → leer, auch in `tools/k3c-dev` (Katalog, Anleitung, Mock, `wails.json`, `services.json`).
- **AC-06** umgesetzt, geprüft: `check_run` startet `task <name>`; `TestCheckRunMusterUndKonsole` in `internal/mcpsrv/check_test.go` belegt `task test -- planning`. `task check:dev` grün.
- Ziele heißen jetzt `task:check`, `task:test`, `task:typecheck`, `task:lint`, `task:build`, `task:check:go` (neu), `go:lint`, `go:test`, `dev:test`; `npm:*` entfällt. `go:test` und `dev:test` bleiben direkte `go test`-Aufrufe, weil sie das `-run`-Muster brauchen (`task go:test` reicht keine Argumente durch); `go:lint` läuft über `task go:lint`.

- `task check:dev` und `task check:go` grün. `task check` lief im Hauptbaum grün bis auf einen Fremdeinfluss (Worktree eines parallelen Agenten unter `.claude/worktrees/` wird von Vitest mit eingesammelt).
