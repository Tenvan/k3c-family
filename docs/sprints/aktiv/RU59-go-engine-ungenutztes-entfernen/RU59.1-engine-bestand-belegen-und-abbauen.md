## Ziel

Der Verbleib jedes Go-Pakets unter `engine/` und `cmd/` ist belegt; alles ohne Importeur, Test und Aufgabe (und der Code, den nur das gelöschte Go-Spiel rief) ist entfernt, die Workbench und `k3c-sim` laufen unverändert.

## Kontext

Schritt 3 der Entscheidung von Ralf (2026-11-19). RU37 hat `native/` entfernt, deshalb gibt es jetzt Engine-Code, den niemand mehr aufruft (z. B. Zugriffe, die nur `native/k3c-game/local`, `game` oder `view` nutzten). Belegt am 2026-11-19: Produktions-Importe der Workbench aus `engine/` sind `simcli`, `store`, `conlog`, `room`, `devrun` (und `data`); transitiv `sim`, `level`, `balance`, `rng`, `enginetools`. `cmd/k3c-sim` importiert nur `tools/checkdiff/simlist_test.go`. `engine/internal/{golden,detvec,trace}` sind Test-Infrastruktur (importiert von `sim`/`level`-Tests und `detvec/data_test.go`). Modul-Lage: Wurzel-Modul `k3c` (`go.mod`), `tools/k3c-workbench` und `tools/assetkit` eigene Module mit `replace k3c => ../..`.

**Bleibt unberührt (Ralf 2026-11-19):** `engine/balance`, `engine/simcli`, `engine/enginetools`, `cmd/k3c-sim`, in der Workbench `internal/balance` und `internal/simrun`: Das Go-Balancing verlässt die Workbench erst in RU40, ganz zum Schluss.

**Verfahren (Beleg, nicht Schätzung):**
1. Pakete: `go list -deps -test -f '{{.ImportPath}}' ./...` im Wurzel-Modul und in `tools/k3c-workbench`, `tools/assetkit`; je Paket unter `engine/` und `cmd/` die Importeure (Produktion und Test) zusammenstellen. Pakete ohne Importeur außerhalb der eigenen Tests und ohne Task (`engine/Taskfile.yml`, `cmd/k3c-sim/Taskfile.yml`, `Taskfile.yml`, `tools/checkdiff`, `tests/projectRules.test.ts`): Kandidat zum Entfernen.
2. Funktionen: `go run golang.org/x/tools/cmd/deadcode@<aktuelle, mindestens zwei Wochen alte Version> -test ./engine/... ./cmd/...` im Wurzel-Modul (nur ausführen, nicht ins `go.mod`; ohne Netz, falls nicht ladbar: Hinweis ins Ergebnis und Suche per `git grep`). Wurzeln: `-test` nimmt die Tests mit; die Workbench-Aufrufe zusätzlich per `git grep -n "engine/<paket>" tools/` je Symbol prüfen (`deadcode` sieht Modulgrenzen nicht, daher manuell gegenprüfen: ein Symbol, das in `tools/k3c-workbench/**` vorkommt, bleibt).
3. Herkunft: Symbol im Tag `go-referenz-final` nur von `native/` genutzt? (`git grep -n <Symbol> go-referenz-final -- native`). Nur dann gilt "nur das Go-Spiel rief es".
4. Entfernen nur eindeutig Unerreichbares; Reflexion, Tabellen, `data/`-gesteuerte oder `//go:generate`-Stellen bleiben. Tests, die ausschließlich entfernten Code prüfen, gehen mit. Aufwand je Commit etwa 150 Zeilen; mehr: in Teilen im selben Commit nur, wenn es reine Löschungen sind, sonst Rest als Punkt für den Hauptrechner.
5. Belegtabelle (Paket → bleibt/entfernt → Beleg) ins Ergebnis, dazu die Liste entfernter Symbole mit Zeilenzahl.

Sim-Code (`engine/sim`, `room`, `level`) nur im eigenen Worktree (B-925): Die Session legt unter `.work/` einen Worktree an (ausdrückliche Anweisung für diesen Sprint), startet dort die Dev-Instanz der Workbench auf eigenen Ports (`task k3c-workbench:dev:worktree`) und bedient sie mit `checkout`.
