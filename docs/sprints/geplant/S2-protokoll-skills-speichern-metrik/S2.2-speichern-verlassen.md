# S2.2 · Speichern beim Verlassen und Trennen, Speicherstand in Spielstand und Liste

- **Status:** offen
- **Typ:** Umsetzung
- **Agent:** autonom
- **Branch:** s2/2-speichern-verlassen
- **Abhängig von:** S2.1, S1.4 (Spielstand Version 3), F2.2 (Migrationsregel, Fixtures `testdata/saves/v<n>/`, `engine/sim/save_migration_test.go`)
- **Tickets:** B-147
- **Kriterien:** AC-03, AC-04

## Ziel

Jedes Gerät, das den Raum verlässt oder dessen Verbindung abbricht, löst eine Speicherung aus; ein Schreibfehler lässt den vorigen Stand unverändert. Der Spielstand nennt Zeitpunkt, Tag, Phase und Stufen der Spieler, und `GET /api/saves` liefert sie für alle Spielstände.

## Kontext

- **Speichern heute** (`engine/room/`): `Room.save()` (`room.go`) ruft `store()` = `json.Marshal(r.isl.ToSave(<jetzt, ISO 8601>))` → `Manager.Store.Store(name, data)`; ein Fehler landet im Log (`Spielstand nicht gespeichert`), der Raum läuft weiter. Gespeichert wird bei jedem Stufenwechsel (`Tick` in `actions.go`, `travelled`), wenn **kein** Gerät mehr verbunden ist (`afterDisconnect` in `actions.go`, aufgerufen aus `leave` und `Drop`), beim Aufräumen nach `EmptyFor` (`lockedSweep` in `manager.go`) und beim Herunterfahren (`closeFinal`). **Nicht** bei Tagesanbruch (die Ausgangslage von B-147 und der Sprint-README nennt das, der Code tut es nicht). Ein Gerät, das geht, während andere bleiben, speichert also heute nicht.
- **Verlassen und Trennen:** `Room.Leave` (Nachricht `leave`) und `RemoveSlot` des letzten Slots → `leave(id)`; Verbindungsabbruch → `Room.Drop` (aus `engine/net/ws.go`, Ende der Lese-Schleife). Beide enden in `afterDisconnect()`; ein geschlossener Raum speichert nicht (Absturz).
- **Atomar** (`engine/store/`): `Saves.Store` prüft Inhalt und Größe, verschiebt den alten Stand in die rotierenden Sicherungen (`backups.go`) oder sichert ein fremdes Spiel als `<slot>-<savedAt>.json`, dann `writeAtomic` (`atomic.go`: Temp-Datei im selben Ordner, `os.Rename`; Fehler → Temp-Datei weg, alter Stand heil).
- **Spielstand** (`engine/sim/island_save.go`, nach S1.4 laut Plan `IslandSaveVersion = 3`, Migration in `island_save_v3.go`; vor dem Start im Code prüfen): `IslandSave` hat schon `savedAt` (Zeitpunkt, vom Raum gesetzt), `time`, `players[].depth`; Tag und Phase stehen nicht drin. Tag und Phase liegen in `World.Cycle` (`CycleInfo{Phase: day|dusk|night, Day, …}`, `engine/sim/cycle.go`); alle Stufen teilen die Inselzeit, `ToSave` nimmt `Time` aus `Stages[0]`. Migrationsregel (F2.2, `docs/arbeitsweise.md` › „Spielstand-Format ändern“): Formatänderung = Version + 1, Fixture `testdata/saves/v<n>/`, Test „alter Stand lädt“; `save_migration_test.go` verlangt ein Fixture-Verzeichnis je Version.
- **Liste:** Es gibt heute **keine** Spielstand-Liste, weder im WebSocket-Protokoll noch über HTTP (`engine/net/handler.go`: `/api/save?slot=…` liest und schreibt einen Stand). `store.Saves` hat `Count` und `Purge`; `parseSave` liest `campaignId`, `savedAt`, `version` generisch (ohne `engine/sim`). Das Entwickler-Werkzeug hat ein eigenes `saves_list` (`tools/k3c-dev/internal/gamedata/saves.go`), es bleibt unverändert.
- Tests: `engine/room/room_test.go` hat 398 Zeilen (`TestSpeicherzeitpunkte`, Fixture `newFixture()` mit `memStore`, der `saves` zählt; Hilfen `need`, `ticks`, `peer`); neue Tests in eine neue Datei. Einen echten Ordner zeigt `engine/room/island_test.go` (`store.Saves{Dir: t.TempDir()}`). `engine/net/handler_test.go` zeigt HTTP-Tests (`TestSpielstandFehler`), `engine/net/memsaves_test.go` einen Speicher für Tests.
- **Entscheidungen dieser Session (Vorschläge der Planung, 🧑 bestätigt oder ändert sie mit der Spec-Freigabe; nicht als Beschluss behandeln):**
  - **Wann:** `afterDisconnect` speichert bei **jedem** Verlassen und jedem Abbruch eines Geräts, nicht erst beim letzten (B-147 › Beispiele: „Gerät 2 trennt → Speicherung“). Der Rest bleibt (Stufenwechsel, leer, Aufräumen, Herunterfahren). **Kein** zusätzlicher Takt (B-147 › Nicht-Ziele; siehe Abschnitt „Offen“ unten).
  - **Felder im Spielstand:** `day` (Zahl) und `phase` (`day`, `dusk`, `night`) aus `Stages[0].Cycle`; die Stufen stehen schon in `players[].depth`. Das ist eine Formatänderung: Version **N → N+1** (nach S1.4 erwartet 3 → 4), Fixture `testdata/saves/v<N+1>/familie.json`. Beim Laden haben `day` und `phase` keine Wirkung (die Zeit kommt aus `time`); ein Stand ohne sie (Version ≤ N) lädt unverändert.
  - **Domäne:** Die zwei Felder und die Version liegen in `engine/sim/island_save.go` (SIM). B-147 nennt diese Datei selbst, und die Sprint-Regel verlangt den Versionssprung; die Session ändert dort nur Felder, Version, Migration und Fehlermeldung, keine Spiellogik. **Grenzfall, 🧑 bestätigt mit der Freigabe.**
  - **Liste:** `GET /api/saves` liefert `[{ "name", "savedAt", "version", "day", "phase", "depths" }]` nach Name sortiert, nur Spielstände (`^[a-z0-9-]{1,32}$`, keine Sicherungen); `depths` = sortierte Tiefen aus `players[].depth`; fehlende Felder fehlen in der Antwort. `store.Saves.List()` liest die Dateien generisch (kein Import von `engine/sim`), eine unlesbare Datei steht mit `"error": "ungültig"` in der Liste statt die Liste abzubrechen. Nur `GET`, kein Token (lesend, wie `GET /api/save`, Beschluss Q17 betrifft Restore). Beschrieben in `docs/protocol.md` als eigener Abschnitt „HTTP: Spielstände“; das WebSocket-Protokoll und seine Version ändern sich nicht, deshalb kein zweites Ende (Anzeige im Client ist Nicht-Ziel von B-147).
  - **Dauer:** Der Raum misst die Speicherdauer und schreibt sie in die vorhandene Log-Zeile (`ms`); über einem Tick (33 ms) als Warnung (B-147 › Anforderungen: „Zielwert in der Spec festlegen“, Vorschlag 33 ms).
- **Offen (nicht in dieser Session):** Beschluss Q10 (`docs/fragenkatalog.md` › Beschlüsse) verlangt zusätzlich „alle 60 s“, Tagesanbruch und HUD „gesichert“. B-147 schließt einen Autospeicher-Takt aus, und AC-03/AC-04 nennen ihn nicht. Bis 🧑 die Spec erweitert, wird **kein** Takt, kein Speichern bei Tagesanbruch und keine HUD-Anzeige gebaut.
- Regeln: Funktion ≤ 60 Zeilen, Datei ≤ 400; `saves/` bleibt die einzige Ablage; Sperr-Reihenfolge Manager vor Raum (`manager.go`).
