### Abweichungen
- „Ohne gh“: Test ruft ein nicht vorhandenes Programm, statt den `PATH` zu leeren.
- `paths: null` wird abgelehnt; neue Dateien `capture.rs`, `github/{client,prs}.rs`, `gitcommit/{status,paths}.rs`; stderr geht beim `WaitDelay`-Ablauf verloren; serde-Texte bei kaputtem JSON.

### Für den Hauptrechner
- **Wie Go:** `git_commit` mit `paths: ["."]` oder einem Ordner nimmt alles darunter mit (auch Dateien einer parallelen Session), entgegen der Beschreibung.
- Wie Go: gestagt wird vor der Prüfung der Nachricht (Index bleibt gefüllt); main-Sperre vergleicht nur exakt `main`; keine eigene Frist für den Commit.
- Wackler im Testlauf unter Windows: `Permission denied` bei git in `.work/tmp` (auch `k3c-studio`), einmal `gitops::repo_tests::status_und_aktionen` (Meldung nicht erfasst), einmal `assetsui::tests::assets_get`. Vermutet: Virenscanner. Ggf. Ticket.
- Ohne eigenen Test: Frist mit Ende des Prozessbaums, `WaitDelay`, `git_commit` mit `checkout` im Worktree.
- Ungeprüft: echte `gh`-Ausgaben, Seiten Git/Planung, Vergleich gegen laufendes Go.
