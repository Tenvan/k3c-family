Vorentscheidungen (Default, autonom, Claude, 2026-11-17; 🧑 kann widersprechen):
- **Kein `Run(ctx)`, kein Ticker:** Gos `Manager.Run` (Goroutine mit `time.Ticker`, `context`) wird `Manager::tick_all(&mut self)` (ein Takt über alle Räume in der Reihenfolge von Go) und `Manager::sweep_if_due(&mut self)` (Aufräumen und Statistik nach den Fristen `sweep`/`statsEvery`, gemessen an der Uhr des Managers). Den Takt von 30 Hz gibt der Aufrufer vor (RU27); Tests rufen `tick_all` selbst. Der Test `TestDreiRaeumeParallel` heißt in Rust sinngemäß `drei_raeume_nacheinander` und prüft, dass drei Räume unabhängig vorankommen; Zeile im Ergebnis.
- **Absturz-Schutz:** `guard(tick)` (Go: `recover`) wird `std::panic::catch_unwind(AssertUnwindSafe(…))`; bei Panik gilt wie in Go `crash` (Raum schließen, `Failure` merken, Text der Meldung übernehmen). Der Test `TestSafeTickPanicSchliesstRaum` löst die Panik über die Test-Naht `before_step` aus.
- **Raum-Code:** `Manager::code` zieht Buchstaben aus `CODE_LETTERS` mit einem `k3c_rng::Rng`, den der Aufrufer beim Anlegen des Managers seedet (`Manager::new(store, env, seed: &str)`); Tests geben einen festen Seed. Gleiche Wahrscheinlichkeitsverteilung wie in Go ist nicht nötig, der Code darf nur nicht doppelt vorkommen (Schleife wie in Go) und muss aus den Buchstaben bestehen (Test). Kein `rand`.
- **Tick-Dauern:** `timed_tick` misst die Dauer über zwei Uhr-Aufrufe (`Env.now`), `durations` bleibt ein Ring von 300 Werten, `p99` wie in Go (Sortieren mit `sort_by(f64::total_cmp)`, kein Gleichstand-Problem bei reinen Zahlen). Die Uhr kann rückwärts laufen: negative Dauern werden wie in Go behandelt (Quelle lesen).
- **`Store`-Interface:** wird `trait Store` (`load`, `store`, `delete`) mit `Result<_, Fehler>`; `store::Saves` implementiert ihn, `MemStore` in `testutil` ebenso. `io.Reader`/`fs.FS`-Parameter von `manager.open`/`island_options` werden `&Source` aus `k3c_data` bzw. `&[u8]`.
- `Manager::open` (Spielstand lädt oder legt neu an), `island_options`, `live_grade`, `seed_of` nutzen `sim::Island`, `sim::IslandOptions` und `create_island_in`/`from_island_save_in` aus RU10; `world(id)`/`load_world` kommen aus RU24 (Platzhalter `world`, `load_world`, `create_in`, `load_in` in `room/pending.rs`, RU24.4 löscht sie). `MaxRooms`, `TestPrefix`, `saveName` (Regex `^[a-z0-9-]{1,32}$`) prüft eine Hand-Funktion `valid_save_name`.
- `Manager::close`/`close_final` schreiben synchron (kein Hintergrund-Schreiber; RU24.2).
