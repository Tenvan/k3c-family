### Vorentscheidungen (Claude, nach Leitfaden)

1. **`proc` ist async auf tokio**, weil alle Aufrufer (MCP-Tools, Dienste, `check_run`) in tokio laufen. Workspace-Abhängigkeit `tokio = { version = "=1.54.1", features = ["process", "rt", "macros", "sync", "time", "io-util"] }` (dev zusätzlich `rt-multi-thread`).
2. **API `proc`:** `pub fn executable(name: &str) -> String` (npm → npm.cmd unter Windows); `pub struct Cmd` mit `Cmd::new(args: &[impl AsRef<OsStr>])`, `command_mut() -> &mut tokio::process::Command` (Dir, Env, Stdio wie bei `exec.Cmd`), `start(self) -> io::Result<Proc>`, `run(self).await`; `pub struct Proc` mit `id()`, `child_mut()` (Pipes), `kill_handle() -> KillHandle`, `wait(&mut self).await` (schließt danach den Job, merkt `exited`); `#[derive(Clone)] pub struct KillHandle` (Send + Sync, intern `Arc<Mutex<State>>`) mit `kill() -> io::Result<()>`: nach `wait` nichts, sonst Job beenden, sonst `kill_tree(pid)`; `pub fn kill_tree(pid: u32) -> io::Result<()>` (Windows `taskkill /T /F /PID`, ohne Fenster). Unter Windows `creation_flags(CREATE_NO_WINDOW = 0x0800_0000)`.
3. **Context-Abbruch:** Go `exec.CommandContext` + `Cancel = Kill` wird zu: Aufrufer nutzt `tokio::select!` und `KillHandle::kill()`. `WaitDelay` (5 s auf Pipes eines Enkels) hat in tokio keine Entsprechung; nicht portieren, im Ergebnis nennen. Kein CTRL_BREAK: das steckt nur in `engine/devrun` (nicht portiert, 014 Punkt 4).
4. **Job-Objekt:** `src/proc/windows.rs`, eingebunden mit `#[cfg(windows)] #[allow(unsafe_code)] mod windows;`, jede `unsafe`-Stelle mit `// SAFETY:`. Crate `windows = { version = "=0.62.2", default-features = false }` als `[target.'cfg(windows)'.dependencies]` mit den Features `Win32_Foundation`, `Win32_Security`, `Win32_System_JobObjects`, `Win32_System_Threading`. Ablauf wie `proc_windows.go`: CreateJobObjectW, SetInformationJobObject mit `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, OpenProcess(`PROCESS_SET_QUOTA | PROCESS_TERMINATE`), AssignProcessToJobObject; jeder Fehler heißt „kein Job“. Handle in einem Typ mit `Drop` schließen. `src/proc/other.rs` portiert `proc_other.go` (Prozessgruppe über `process_group(0)`, Abbruch per `kill -KILL -<pid>`), nur damit das Crate außerhalb von Windows übersetzt.
5. **Test-Helfer:** `TestHelperProcess` wird zu `#[test] fn helper_process()`, das sofort zurückkehrt, außer die Umgebung `K3C_PROC_HELPER` ist gesetzt; die Tests starten `std::env::current_exe()` mit `--exact proc::tests::helper_process --nocapture` und dieser Umgebung (Adress-Datei unter `testutil::tmp_dir()`).
6. **`usage` nur mit `std`** (Threads, kein tokio), damit es unabhängig von der Laufzeit bleibt. Uhr injizierbar: `pub type Clock = Arc<dyn Fn() -> chrono::DateTime<chrono::Local> + Send + Sync>`. `Tracker::new(now: Clock)`, `Tracker::open(path, now, on_err: Arc<dyn Fn(&str) + Send + Sync>) -> Arc<Tracker>` (Fehlertext wie `err.Error()` in Go), `record(Event)`, `snapshot() -> Usage`, `flush() -> io::Result<()>`. Gebündeltes Speichern wie `scheduleSave`: ein Merker (`AtomicBool`) plus ein Thread, der die Go-Verzögerung schläft und dann `flush` ruft.
7. **Formen:** `Event`, `Count`, `ToolUsage`, `Scope`, `Usage`, `Bucket`, `SlowCall` mit `#[serde(rename_all)]` bzw. `rename` exakt nach den `json:`-Tags in Go (die Oberfläche liest sie, `src/api/types.ts` der Workbench). Die Datei (`fileData` in `persist.go`) bleibt lesbar in beide Richtungen: Zeiten als RFC 3339 (chrono-serde); Bitgleichheit ist nicht nötig (Entscheidung 012), wohl aber, dass eine Go-Datei geladen wird: Fixture `rust/tools/crates/k3c-kit/testdata/usage-go.json`, von Hand nach `fileData` und Go-Zeitformat (RFC3339Nano) gebaut, Test lädt sie.
8. **Determinismus:** Go `sort.Slice` ist nicht stabil; wo Ranglisten bei Gleichstand sortieren, die Go-Schlüssel nachbilden und bei Gleichstand nach Name sortieren; Abweichung im Ergebnis nennen. Fließkomma-Formeln (Histogramm, Perzentile, Ausreißerregel) Zeichen für Zeichen übernehmen.

### Fallstricke

- `chrono::Local` in Tests: feste Zeitpunkte mit `Local.with_ymd_and_hms(…)`; Minutenwende-Test (`TestMinutenwendeInBeliebigerReihenfolge`) mit Unix-Minuten wie Go.
- Datei-Tests (`TestNichtSchreibbarWarntEinmal`, `TestZweiteSicherungUeberschreibtErsteNicht`) nur unter `testutil::tmp_dir()`.
