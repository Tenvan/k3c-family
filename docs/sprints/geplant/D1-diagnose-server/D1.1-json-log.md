# D1.1 · JSON-Log des Servers und Log-Quelle in k3c-dev

- **Status:** offen
- **Typ:** Umsetzung
- **Agent:** autonom
- **Branch:** d1/1-json-log
- **Abhängig von:** –
- **Tickets:** B-066
- **Kriterien:** AC-01

## Ziel

`k3c-server` schreibt sein Log zusätzlich als JSON nach `logs/k3c-server.jsonl` (wenn ein Log-Ordner da ist), und k3c-dev führt den Dienst „Heimnetz“ mit dieser Log-Quelle.

## Kontext

- Das Feld `Start-Commit` des Sprints setzt diese Session: `git rev-parse --short origin/main` vor dem Branch.
- Heute: `cmd/k3c-server/main.go` baut `slog.New(slog.NewTextHandler(os.Stderr, nil))` und gibt den Logger an `run(cfg, log)`; `loadConfig()` liest die Umgebung (`K3C_HTTP_PORT`, `K3C_DIST`, …). Es gibt keine Log-Datei.
- Format wie k3c-dev (`tools/k3c-dev/internal/applog/applog.go`, B-046): eine JSON-Zeile je Eintrag mit `time` (RFC 3339 mit Zone), `level` (`DEBUG`, `INFO`, `WARN`, `ERROR`), `msg`, optional `ns`, weitere Felder = Daten. Der Log-Leser `tools/k3c-dev/internal/logs/entry.go` liest das; `slog.NewJSONHandler` liefert `time`, `level`, `msg` (Level in Großbuchstaben) von allein. Vor dem Schreiben prüfen, dass k3c-dev eine so erzeugte Zeile liest (Test mit einer echten Zeile).
- Ordner (B-066 › Anforderungen): `K3C_LOG_DIR`, sonst `logs/` im Arbeitsverzeichnis, **wenn dieser Ordner schon existiert**. Sonst keine Datei, nur stderr. Nicht schreibbar → Warnung auf stderr, weiter nur mit stderr. Datei mit `O_APPEND|O_CREATE`.
- Zwei Handler gleichzeitig (Text auf stderr + JSON in die Datei): kleiner Fan-out-Handler mit der Standardbibliothek (`slog.Handler` mit zwei Zielen), kein Fremdpaket. `Enabled` ist wahr, wenn einer der beiden es ist; Fehler eines Ziels dürfen das andere nicht verhindern.
- Keine Tokens im Log: `K3C_STATUS_TOKEN` wird heute nicht geloggt (nur „diagnose aus“); so lassen.
- `tools/k3c-dev/services.json`: Dienst „Heimnetz“ bekommt `"log": "k3c-server"` (das Feld heißt `log`, Beispiel siehe `internal/services` und `adopt_test.go`). Der Test, der `services.json` lädt, steht in `tools/k3c-dev` (`main_test.go` oder `internal/services`); sonst einen kleinen Test ergänzen, der die echte Datei lädt und `Log == "k3c-server"` prüft.

## Erlaubte Dateien

- `cmd/k3c-server/**` (Log-Aufbau in einer neuen Datei `logging.go`, Tests dazu)
- `tools/k3c-dev/services.json` und Tests in `tools/k3c-dev/`, die sie laden
- `README.md` (ein Satz zu `K3C_LOG_DIR` bei den Umgebungsvariablen)
- `docs/sprints/`, `docs/backlog/`

## Nicht-Ziele

Log-Rotation; Änderungen an `engine/`; die Diagnose-Endpunkte (D1.2 und D1.3); Taskfile oder Dockerfile.

## Schritte

1. `git rev-parse --short origin/main` → Feld `Start-Commit` der Sprint-README setzen. Branch `d1/1-json-log`, `Status: in Arbeit`.
2. `logging.go`: `newLogger(dir string, stderr io.Writer) (*slog.Logger, func())`: Ordner bestimmen (`K3C_LOG_DIR`, sonst vorhandenes `logs/`), Datei öffnen, Fan-out aus Text- (stderr) und JSON-Handler (Datei); schließen-Funktion zurückgeben; bei Fehlern nur stderr plus Warnung.
3. `main.go` benutzt `newLogger`; `defer` das Schließen. Bestehende Meldungen bleiben, ihre Felder wie bisher.
4. `services.json` um `"log": "k3c-server"` ergänzen.
5. Tests: (a) mit gesetztem Ordner steht nach `log.Info("x", "ns", "test")` eine gültige JSON-Zeile in `k3c-server.jsonl` mit `level` `INFO` und `ns` `test`, und derselbe Eintrag als Text in `stderr`; (b) ohne Ordner entsteht keine Datei; (c) nicht beschreibbarer Pfad (z. B. eine Datei statt Ordner) → nur stderr plus Warnung; (d) die Zeile aus (a) liest `tools/k3c-dev/internal/logs` (`logs.Scan`) als Eintrag mit richtigem Level; (e) `services.json` enthält „Heimnetz“ mit `log` `k3c-server`.
6. `task check:go` und `task check:dev` → grün.
