## Ziel

`task check:diff` (samt `:plan`, `:js`, `:rust`) und `task ops:aufraeumen` laufen über TypeScript-Fassungen unter bun (`tools/checkdiff/*.ts`, `tools/cleanup/*.ts`) mit portierten Tests und gleichem Verhalten wie die Go-Fassung; die Go-Dateien bleiben bis RU71.4 liegen.

## Kontext

Leitfaden `docs/standards/rust-werkzeuge.md`; Entscheidung für RU71 (Claude, Planung 2026-11-26): **Das Repo wird Rust + TypeScript. Go-CLIs, die nur Prozesse, Git und Dateien orchestrieren, werden TypeScript unter bun** (wie `tools/paper`, `tools/rigexport`): kein Bauschritt vor `check:diff`, Tests im Vitest der Wurzel, Lint/Typecheck der Wurzel. Orakel ist die Go-Fassung (Entscheidung 012 sinngemäß): gleiche Flags, Ausgaben, Exit-Codes.

### checkdiff (Go: 813 Zeilen, 286 Test)

- Dateien: `tools/checkdiff/main.go` (Flags `-base`, Umgebung `CHECK_BASE`, `-plan`, `-only js|go|rust`, `-gopkgs`, `-wbpkgs`), `select.go` (reine Auswahl `classify` ohne Git und Dateisystem), `repo.go` (Git: `changedFiles`, Basis HEAD, sauberer Checkout → HEAD~1; `go list`), `steps.go` (Schritte je Bahn und Stufe), `rust.go` (Crates unter `rust/` und – seit RU66.1 – `rust/tools/`), `run.go` (Bahnen parallel, Schritte einer Bahn nacheinander bis zum ersten Fehler, Ausgabe nur bei Fehler), `gopkgs.go`. Beschreibung: `tools/checkdiff/codemap.md`. Tests: `select_test.go` (Tabelle), `simlist_test.go`.
- **Zeitmarker exakt beibehalten:** `⏱▶ <name>` vor und `⏱■ <name> exit=<n>` nach jedem Schritt; `check_run` der Workbench liest sie.
- **Nicht portiert:** Bahn `go`, `-gopkgs`, `-wbpkgs`, `simlist_test.go` (Go wird in RU71.4 gelöscht; bis dahin ändert keine Session Go-Code). `check:go` und `k3c-workbench:gotest` rufen bis RU71.4 weiter `go run ./tools/checkdiff -gopkgs|-wbpkgs`; darum bleiben die Go-Dateien hier unberührt. `-only go` lehnt die TS-Fassung mit Meldung und gültigen Werten (`js`, `rust`) ab.

### cleanup (Go: 430 Zeilen, 358 Test)

- Dateien: `tools/cleanup/main.go` (Git- und `gh pr list`-Aufrufe), `cleanup.go` (Branches und Worktrees: nur sichere Fälle löschen, Rest mit Grund listen, auf `origin` nie), `bin.go` (alte EXE entfernter Programme in `bin/`, B-1007); Tests `cleanup_test.go` (Git-Repo im Temp-Ordner), `bin_test.go` (Junction per `mklink /J`, nur Windows). Aufruf heute: `scripts/Taskfile.yml` › `aufraeumen` baut `bin/aufraeumen.exe`; `--dry` zeigt nur an.
- Einzige gewollte Verhaltensänderung: Die Liste alter EXE in `bin/` bekommt `aufraeumen`, `regeltabelle` und `soundatlas` dazu (Go-EXE, die seit RU71 als TypeScript laufen).

### Technische Vorgaben

- Nur Node-APIs (`node:child_process` `spawnSync`/`spawn`, `node:fs`, `node:path`), keine Bun-Globals: Vitest der Wurzel läuft unter Node (`tests/tsconfig.json`: node-Typen). Aufruf `bun tools/checkdiff/main.ts …`.
- Reine Logik getrennt von Git und Dateisystem (wie Go: `select.ts` ohne Seiteneffekte), damit die Tabellen-Tests ohne Repo laufen.
- Tests neben dem Code: `tools/checkdiff/*.test.ts`, `tools/cleanup/*.test.ts` (der Vitest der Wurzel findet sie; `vitest.config.ts` schließt sie nicht aus). Temporäre Repos unter `.work/tmp/` (`mkdtempSync`), danach löschen; Junction-Test mit `it.skipIf(process.platform !== 'win32')`.
- `tsconfig.json` › `include` um `tools/checkdiff` und `tools/cleanup` erweitern.
- Datei ≤ 400, Funktion ≤ 60 Zeilen, Oxlint-Regeln der Wurzel.
- Seit RU71.1 läuft die Rust-Workbench auf 5180 (MCP wie gewohnt; Rückfall per curl siehe RU71.1 Schritt 9).

## Schritte

1. `git merge origin/main`. Orakel festhalten, bevor etwas umgestellt wird: `mkdir -p .work/orakel`; `task check:diff:plan > .work/orakel/plan-head.txt`; `CHECK_BASE=origin/main task check:diff:plan > .work/orakel/plan-main.txt`; `task ops:aufraeumen -- --dry > .work/orakel/cleanup-dry.txt`.
2. `tools/checkdiff` nach TypeScript: `main.ts` (Flags, Exit-Code), `select.ts` (aus `select.go` und `rust.go`, ohne Go-Module), `repo.ts` (nur Git), `steps.ts` (Bahnen `js` und `rust`), `run.ts` (Stufen, Parallelität, Zeitmarker). Tests: `select.test.ts` portiert jede Zeile aus `select_test.go`, die keine Go-Datei betrifft; Zeilen nur für Go entfallen (Anzahl im Ergebnis nennen). Dazu ein Test für das Format der Zeitmarker.
3. `tools/cleanup` nach TypeScript: `main.ts`, `cleanup.ts`, `bin.ts`; Tests `cleanup.test.ts`, `bin.test.ts` aus den Go-Tests; Liste alter EXE erweitern (Kontext).
4. `tsconfig.json` erweitern; `Taskfile.yml`: `check:diff`, `check:diff:plan`, `check:diff:js`, `check:diff:rust` rufen `bun tools/checkdiff/main.ts …` mit denselben Argumenten; `check:diff:go` entfällt; Beschreibungen ohne `go vet`. `check:go` bleibt unverändert. `scripts/Taskfile.yml` › `aufraeumen`: `bun tools/cleanup/main.ts {{.CLI_ARGS}}`, Vorbedingung Go entfällt.
5. Orakel-Vergleich: dieselben drei Befehle wie in Schritt 1 erneut nach `.work/orakel/*-ts.txt`; `diff` gegen die Go-Ausgaben. Erlaubte Unterschiede nur: fehlende Schritte der Bahn `go` und die drei neuen EXE-Namen. Jeder andere Unterschied wird behoben.
6. `tools/checkdiff/codemap.md` und `tools/cleanup/codemap.md` auf die TS-Fassung umschreiben (Hinweis: Go-Dateien nur noch für `-gopkgs`/`-wbpkgs`, Löschung in RU71.4).
7. Gezielt: `bunx vitest run tools/checkdiff tools/cleanup`, `task lint`, `task typecheck`. Dann `task check:diff` (die neue Fassung prüft sich selbst) über `check_run`. `.work/orakel/` löschen.
8. Ergebnis (Orakel-Vergleich mit Zahl der portierten und entfallenen Tests) eintragen, Status `fertig`, ein Commit, Push.

- AC-03: umgesetzt. `check:diff`, `:plan`, `:js`, `:rust` laufen über `bun tools/checkdiff/main.ts`; `check:diff:go` ist entfernt, `-only` mit anderem Wert bricht mit Meldung ab.
- geprüft: `bunx vitest run tools/checkdiff tools/cleanup` (5 Dateien, 70 Tests), `task lint`, `task typecheck`, `check:diff` grün. Orakel auf Wegwerf-Repo: 177 von 179 Aufrufen gleich, 2 unterscheiden sich nur durch das entfallene `go-vet` für `go.mod`; `-plan` auf dem echten Repo gleich.
- `ops:aufraeumen` läuft über `bun tools/cleanup/main.ts`; Go gegen TS auf gleichen Wegwerf-Repos (dry und echt): gleiche 17 Zeilen und gleicher Endstand. Die drei neuen EXE-Namen deckt ein Unit-Test.
- Portierte Tests: TestClassify (15 Zeilen, davon 10), TestJsSteps, TestRustSteps, TestToolsRustSteps samt Grenzen, alle 11 cleanup-Tests. Entfallen: 5 Tabellenzeilen nur für Go und 7 Funktionen für Bahn go bzw. Paketlisten (TestGoStepsNurGeaendertePaketeTesten, TestSimSperreAufgehoben, TestAbnehmerInAnderemModulNurVet, TestSpielModul, TestSimListeGleich, TestFilterPkgs, TestFilterPkgsStudio).
- Abweichungen: cleanup strenger (lose Argumente Exit 2, Branches mit führendem `-` bleiben); checkdiff lehnt eine Basis mit führendem `-` ab; Programme nur über absoluten PATH, unter Windows nur `.exe`/`.com`, ohne Shell; Reihenfolge von stdout/stderr nur ungefähr; `-gopkgs`, `-wbpkgs`, `-studiopkgs`, `CHECK_SIM` entfallen; cleanup löscht auch die EXE soundatlas und aufraeumen; `main.ts` getrennt von `app.ts`.
- Review (zwei Befunde behoben): Änderungen an `tools/checkdiff` und `tools/cleanup` bekommen wieder Lint, Typecheck und Vitest; ein vertipptes `-only` meldet nicht mehr grün.
- ungeprüft: `check_run`-Marker der Workbench vor diesem Commit, cleanup auf dem echten Repo, echtes `gh`, clippy/Tests über den TS-Läufer, wirklich gesperrte Datei, Linux/CI, Junction-Erkennung unter bun (Tests laufen unter vitest/node). Die Go-Dateien sind unverändert.
